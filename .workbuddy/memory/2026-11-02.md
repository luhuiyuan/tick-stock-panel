## 07:30 修复 minute bar 被集合竞价虚拟撮合污染（真 bug）

### 问题
`_ticks_to_bars` 只过滤了 `minute_of_day < 565`（09:25 前），漏掉 **14:57~14:59 的
`direction=8` 虚拟撮合记录**。它们的 `minute_of_day` 是 897~899，落在合法区间内；
14:59 那条 `+1 分钟` 后正好是 15:00，被 `min(stamp, last_bar)` 夹进收盘那根 bar。

后果（2025 年 30 只 / 7290 个股票日实测）：
- **19.7% 的股票日**（382/1944 抽样）15:00 那根 bar 的 `open`/`low` 被拽到试探价
  （000001.SZ 2025-07-22：未过滤 open/low=12.48，官方 12.49）
- 还多出 14:58 / 14:59 的**幽灵 bar**：修复后每日最大根数从 240 降到 239
- 修复后 15:00 那根 **100% 满足 O=H=L=C**（收盘只有一笔竞价成交）

### 逐笔数据准确性验证（用户要求）
30 只 × 243 天 = 7290 个股票日，六维度核对：
| 维度 | 结果 |
|---|---|
| 开盘价 / 收盘价 | **100% 精确** |
| 成交量 | 61.25% 相等，其余**恒差 +1 手** |
| 最高 / 最低价 | 70.77% / 75.84%，最大差 0.4 元 |
| 成交额 | 相对误差中位 0.0078%，最大 0.26% |
| 时间越界 | 0 条；243 天末笔全为 15:00 |
| price<=0 | 0 条 |

根因三条，全部是**数据源粒度**不是抓取问题：
1. **数据源不是逐笔成交，是每 3 秒一个成交汇总**。铁证：单分钟最多 20 条（60/3），
   从未超过，满格分钟 26,048 个；单日 3939~4735 条（上限 4800）。
2. 成交量 +1 手：官方对**总量**向下取整（74,786,237 股 = 747,862.37 手 → 747,862），
   逐笔对**每笔**四舍五入后累加（→ 747,863）。差额只可能 0 或 +1，+1 占 38.75%
   正好对应末两位小数 >0.5 的概率。
3. high/low 差 0.4 元：3 秒切片只保留末价，**切片内极值成交被丢弃**。要精确
   high/low 用日K，不要从逐笔聚合。

另：`direction=2` 不只在竞价时段，盘中也有（切片内买量=卖量无法判向）；
`direction=8` 的**成交量恒为 0 而价格是试探价**，算任何价格指标前必须过滤
（未过滤时开盘价只有 49.93% 对得上，过滤后 100%）。另有少量 0 手但价格正常的
占位记录（28 条/30 只·年，dir 为 0/1），算笔数/笔均量前要滤掉。
