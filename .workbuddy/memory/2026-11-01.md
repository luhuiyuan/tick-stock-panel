## 分钟K「数据源未提供」根因（84224262）

用户报 `/api/kline/minute?symbol=002172.SZ&date=2026-10-30&live=1` 返回空、前端提示
「该日暂无分钟数据（数据源未提供）」。`data/kline_minute` 当时是空目录，但根因不是没数据，
而是 qatdx 的 `get_minute` 每次都在第一根就崩：

```
custom minute provider qatdx call failed; not falling back to TickFlow:
can't compare offset-naive and offset-aware datetimes
```

`fetch_minute_single` 传的是带 `CN_TZ` 的端点（代码注释专门解释了为什么必须带时区），
而 `qatdx.provider._bar_datetime` 明确 `replace(tzinfo=None)` 返回 naive 墙钟，
`stamp < start` 直接 TypeError；`_try_custom_minute` 的契约是 fail-closed（不跨源回退），
于是返回空 DataFrame → `source: "none"`。

### 三个独立缺陷（一起修，缺一个都还是错的）

1. **时区**：加 `_as_naive_cn()`，端点 aware → 北京墙钟 naive，与回包同口径。
2. **取数窗口**：`count` 原来按「查询区间宽度」算。pytdx 的 `start` 是「从最新一根往回数」，
   查历史某天时只取 240 根 → 永远只有最近那天 → 过滤后恒空。改成
   `span_days = today - start.date()` 倒推（自然日 ×0.8× 每天根数，上限 `_MAX_BARS=20800`）。
3. **成交量量纲**：分钟源给的是**股**，日K/面板契约是**手**。实测 002172.SZ 2026-10-30
   1m/5m/15m/30m/60m 各自求和都是 229,468,900 股，同日日K 2,294,688 手 → 差 100 倍。
   加 `_shares_to_lots()`。amount 两边都是元，不用换。

### 顺带修的 pytdx 解包残值

`pytdx.helper.get_volume` 是通达信压缩浮点解包，原始值高位字节为 0 时返回 **2^-127
(≈5.877e-39)** 而不是 0 —— 成交量为 0 的那一分钟会落成 `0 < vol < 1` 的假值。
`client.stock_bars` 里统一把小于 1 的正数归 0（最小成交单位 1 手）。
