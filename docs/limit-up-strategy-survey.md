# A 股打板相关仓库评估

评估日期：2026-10-21。

这次只下载和阅读公开仓库，没有把它们接入本系统，也没有运行其中的下单程序或未知二进制文件。源码快照放在仓库外：

`/home/ashare-limitup-survey`

该目录不进入 Git。临时目录可能被清理，所以上面的路径才是这次留下的副本。

## 结论

不把这 8 个仓库集成进当前系统。

本仓库已经有日线级涨停和连板策略，能覆盖这些项目里可以在日线矩阵上表达的部分。它们多出来的能力主要是盘中封单、排板、扫板、炸板回封和实盘发单。这些能力依赖 QMT、掘金、东方财富接口，或者只有二进制，当前日线矩阵和回测引擎表达不了，也不能安全地整仓搬进来。

如果以后要补打板能力，应在本仓库现有策略和数据上单独设计，不复制这些仓库的代码，也不接入它们的实盘下单。

## 本系统已有的相近策略

位置：`data/strategies/custom/`。它们都是日线矩阵策略，使用已有的涨停标记、连板和换手等字段。

| 策略 | 作用 |
|---|---|
| `active_limit_gene` 涨停基因活跃股 | 近 60 日涨停次数达标，且当日未涨停、缩量休整 |
| `consecutive_limit_ups` 连板股 | 当日涨停且连板不少于 2 |
| `custom_consecutive_limit_ups_v2` 连板股·改进版 | 2 到 4 板，带退出和止损 |
| `custom_two_board_special` 2 连板特别版 | 在可买入的 2 连板里按持有收益评分，而不是追买不进的涨停 |
| `limit_up_momentum` 连板接力 | 近 2 日涨停且当日涨幅超过阈值 |
| `broken_board_recovery` 断板反包 | 连板后断板 1 到 2 天，再放量反包 |
| `near_limit_up` 逼近涨停 | 涨幅较高且接近涨停价 |

日线矩阵已有 `signal_limit_up`、连板次数和换手率。没有买一封单金额、逐笔排队、炸板次数和回封时刻。竞价链路目前也会因数据源不可用而跳过补跑。因此盘中打板不能伪装成一个新的日线策略文件。

## 分仓库评估

### limit-up-sniper

首板研究加执行系统，约 131 个 Python 文件，带测试。流程是：用近 250 日封板率、次日红盘率和次日溢价给股票打分，盘中再过滤情绪、板块、换手和量能，然后选择排板或扫板。排板看涨停价封单，扫板看卖一已经到涨停价时的可见卖盘。执行层是迅投 QMT，另有模拟经纪和 Tick 回放。

特点是规则写得最完整，而且把“历史股性”和“盘口触发”分开。不能集成：它是另一套交易进程，依赖迅投、东方财富和同花顺抓取。MIT 允许借鉴思路，但不把交易引擎并进本仓库。日线部分与现有“涨停基因活跃股”重叠；封单和扫板没有对应字段。

### QMT-QuantLimit

面向 miniQMT 的打板脚本。读取当日涨停价和股票池，在价格到达涨停时下单。选股还包含股吧舆情，但关键选股文件是 `.pyc`，规则不能审计。Apache-2.0 可以依法使用源码，不能恢复并接入看不清的字节码。本系统也没有 QMT 账户接口。

### daban

自动盯盘发单工具。公开部分主要是各平台二进制，以及一个选股脚本和触发参数。参数包括持仓数、单笔金额、观察秒数、涨幅阈值、秒均涨幅、换手和成交额。作者写明选股和是否排板要人工决定，默认不做自动排撤。

92M 里大部分是可执行文件。这次没有运行。没有许可证，不能把二进制引进本仓库，也不能把它当成可审查策略。

### Quantitative-strategy

仓库是多个指标笔记本加一个掘金策略文件 `打二板策略2025.5.26.py`。打二板只做主板，市值、成交额、开盘涨幅和获利盘都有区间，并用左压成交量过滤；卖出看 11:28 和 14:50 两个时点。它依赖掘金的行情、持仓和定时接口。

与本仓库 `custom_two_board_special` 目标相近，但后者已经按“第二天买得进的样本”重做过评分。没有许可证，不复制这份掘金脚本。不需要再进一个二板策略，除非先证明它和现有特别版的信号不同。

### xunlongjue_doc

克隆结果只有 `README.md`、`index.html` 和群二维码、收款码图片，没有策略源码。页面描述的是首板一进二、竞价评分和每日最多 3 只推送，收益数字是作者自述。不能集成，也不能据此重写一套同名策略。

### skill-b6-limitup-pool

涨停池数据处理，不是买卖策略。它给每只股票标记首板、连板数、炸板次数、回封时间、题材和晋级率，输出表格和 HTML。精确炸板次数依赖分钟线；没有分钟线时用日线代理。运行依赖 panda-data 账号。许可证是 GPL-3.0-only。

这类涨停池最接近本系统还没有的复盘视图。因为 GPL 和外部账号，不复制它的脚本。若要做，只能用本仓库日线涨停标记自行统计连板晋级和粗略断板，并在文档里写明日线无法得到真实回封时刻。

### plank

2022 年的 Java 项目。抓取日线和雪球龙虎榜，按龙虎榜净流入排名模拟买卖，并统计连板晋级率。作者自己说明这不是盘中打板。依赖登录 Cookie，项目停更较久，也没有看到许可证。不迁移爬虫和自动操盘。晋级率这个想法与上面的涨停池重复。

### short-term-stock-picker

AKShare 选股脚本，MIT。条件是近 20 日至少一次涨停、总市值不超过 150 亿、收盘在 MA5/10/20 之上且均线多头、换手率 0.5% 到 10%、近 5 日量比大于 1。它筛选的是强势股，不是封板买入。

和现有“涨停基因活跃股”加均线类策略重叠。数据源也不是本系统的矩阵，而是逐只调用 AKShare。不单独接这条抓取链路。若只想要这组过滤，可以以后用现有字段写一个很薄的矩阵策略，不需要这个仓库。

## 集成判定

| 仓库 | 判定 | 原因 |
|---|---|---|
| limit-up-sniper | 不集成 | 价值在盘口和 QMT 执行；日线基因已有替代 |
| QMT-QuantLimit | 不集成 | 实盘接口加不可审计字节码 |
| daban | 不集成 | 无许可证的二进制发单器 |
| Quantitative-strategy | 不集成 | 掘金脚本，且与现有二板策略重复 |
| xunlongjue_doc | 不集成 | 没有可运行代码 |
| skill-b6-limitup-pool | 不集成 | GPL，且依赖外部账号；只保留思路 |
| plank | 不集成 | 旧爬虫和龙虎榜排名，不是打板 |
| short-term-stock-picker | 不集成 | 与现有日线筛选重叠，另走 AKShare |

日线侧已经补了三个股票因子：20 日摸板未封次数、涨停次日开盘溢价、涨停次日收盘溢价。口径和落地限制见审计文档。涨停池复盘视图还没有做。这些都不从上述仓库拷贝代码，也不做排板或扫板。盘中封单策略要等有稳定的逐笔或五档数据后再单独立项。

这次没有修改现有策略、数据源或正在运行的服务。

深度规则、数据源和三层映射见 [limit-up-strategy-audit.md](limit-up-strategy-audit.md)。
