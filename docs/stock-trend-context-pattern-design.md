## 当前实施调整（2026-10-08，优先于下文旧 DP 设计）

本期仅实现 L0/L1 的图表结构验证，不实现概率统计或扩展 L2/L3。

- L0 原样复用市场结构 `swing_points`，日期、high/low 拐点价格、确认日期一致，不改变 SMC 算法。
- L0 使用左右各 3 根 K 线的市场结构局部极值；L1 使用左右各 7 根 K 线的同一算法。两层均使用 high/low 定位和 close 确认，L1 不再使用固定 ATR 反向幅度状态机。
- L1 是原始日 K 线上的更大观察窗口层，而不是把 L0 点再次按 ATR 合并；这是为了让“左右 7 根 K 线”有明确含义。后续若要求严格逐级递归，再单独设计 L0 点上的窗口单位。
- 本期扩展 L2：在原始日 K 线上使用左右各 15 根 K 线的同一市场结构算法，确认延迟为 15 根日 K。L2 默认关闭，仅作为独立视觉层供人工观察；L0/L1 算法和默认显示不变。L2 仍不是严格的 L1→L2 递归层，后续是否递归需单独评估。
- 不使用反向时长、最短长度、DP 偏离或 Z 状态。持续时间按实际交易日索引计算，共享拐点计入相邻段端点。
- 两层的确认边界分别为拐点右侧 3 根、7 根 K 线完成；候选尾段不是已确认 L1 波段。
- 实线展示完整波段，虚线展示从最新已确认 L1 转折到当前候选极值的尾段；日 K 最新收盘不触发 L1 反转。
- L0 暂不人工补首尾点，以确保正式折线与现有市场结构逐点一致。
- 现有 SMC 快照可能修订过去拐点，未来统计必须逐日重放，不能将快照的 `confirmed_date` 当作永久稳定的历史可用证明。
- API 新增 `wave_structure`（L0/L1/L2），暂保留 `dp_structure` 旧字段供兼容；页面展示新字段，按钮支持 L0/L1/L2，默认只开启 L1。
- 历史 DP 算法及测试暂留作兼容，不作为本期页面的波段核心。下文四级 DP 及收盘价口径属于旧方案，不再指导本期实现。

验收：L0 与市场结构逐点一致；小回调合并；大反转在极值处划界；新旧尺子独立；上层点来自下层；确认日不提前；图表切换保持视窗。

## 周线/月线可视化调整（2026-10-09）

- 个股分析增加日线 / 周线 / 月线切换，各自显示真实对应周期的 K 线、成交量与市场结构折线；不把周/月结构混画在日线上。
- 日线保留现有 L0（窗口 3）/L1（窗口 7）；周线/月线为独立背景周期，不命名为 L2/L3，也不沿用日线分级波段。
- 周线按自然周（周一开始）聚合，月线按自然月聚合；open 首值、high 最大值、low 最小值、close 末值、volume 求和。价格来源仍为仓库的前复权日线。
- 聚合后的日期为该周期最后一个有数据交易日，蜡烛与拐点/确认日期使用同一日期轴。ATR14 在周/月 OHLC 上通过现有指标流水线独立重算（Wilder 平滑），不复用日 ATR。
- 周/月结构复用现有市场结构算法，窗口配置均为 3；确认延迟单位是对应周期 K 线，而不是 3 个交易日。
- 默认周线读取近 5 年，月线读取近 10 年；各自提供更长范围及自定义日期选择。只读取仓库已有历史，不自动触发外部历史同步。
- 不依赖交易日历判定完整周期：保守排除输入的首尾周期桶，避免范围起点截断或末期未完成。即使首尾周期实际上已经完整，也暂不显示；界面明确提示此限制、截至日期、周期数。
- 周/月视图本期只展示 K 线、成交量、结构与聚类参考价；不显示日线关键价位、通道指标或日线 L0/L1。后续若扩展周期价位，需独立核对标签和窗口单位。
- 日线多周期背景采用独立长历史（周 5 年、月 10 年，以日线所选截止日期为右端），不再被日线短范围限制。用户手动调整周/月范围后，结构可因输入历史差异而不同。
- 不足两组已确认高低点时，显示“数据不足：尚无两组已确认高低点”，不把不足样本解释为震荡或多空信号。
- 切换股票、日期范围或日/周/月周期时重置视窗；当前周期内的结构/价位开关、主题和刷新保留用户缩放与平移。
- API 在 `/api/stock-analysis/levels` 新增可选 `timeframe=D|W|M`（默认 D，兼容旧调用）；W/M 返回 `rows`、对应 `structure`、日期和周期收盘价，日线指标字段为空，日线返回契约不删除。前端查询键区分周期和范围。
- 当前结果是观察时点的结构快照，仍可能随更多数据修订；不能直接当作无未来信息的历史信号，回测须逐时点重放。

验收：聚合 OHLCV、独立 ATR、周期蜡烛和折线日期对齐、长历史请求、自定义范围、空数据、周期切换、同周期开关视窗保留。

## 1. 方案目标

构建一个基于 A 股日线数据的历史走势模式统计系统，将每个交易日的走势表达为：

```text
最近 K 个已完成中层周期
+
当前未完成中层周期
+
当前层级波段
```

系统在历史样本库中检索相同或相近的走势表达式，统计这些历史样本在未来 5、10、20 个交易日的收益分布。

第一阶段不直接假设系统能够形成稳定交易策略，而是验证以下核心假设：

> 相比只看当前状态，加入前序周期演变上下文，是否能够对未来收益提供稳定的信息增量？

系统的第一目标是形成一个：

- 可解释；
- 无未来函数；
- 可逐日回放；
- 可滚动验证；
- 能输出完整收益分布；
- 可作为后续选股、风控和策略过滤器的走势模式统计引擎。

## 3. 整体架构

```text
原始日线数据
    ↓
统一价格口径与数据质量校验
    ↓
ATR 归一化 DP（L0）：日线 → L0 波段
    ↓ 已完成的 L0 波段
ATR 归一化 DP（L1）：L0 波段轨迹 → L1 波段
    ↓ 已完成的 L1 波段
ATR 归一化 DP（L2/L3）：逐级输入 → 更大级别波段
    ↓ 选择表达式所用层级
    ↓
当前时点上下文表达式生成
    ↓
逐日历史样本库构建
    ↓
精确模式检索与条件概率统计
    ↓
滚动验证与模型 A/B/C 对照
    ↓
实验报告与是否进入下一阶段的决策
```

已确认采用逐级处理，而非每层独立扫描日线。各层复用同一套 ATR 归一化 DP；容忍倍数按层级独立配置并固定。层级数量不限定为三层；第一版使用 L0/L1/L2/L3，后续可按同一算法扩展 L4 及以上。

```text
L0 输入：日线，只输出 UP / DOWN；
L(n)（n >= 1）输入：已经完成的 L(n-1) 波段；
未完成的下一级波段不能作为完整输入提前提交上一级；
第一版不派生 Z 震荡状态。
```

高层波段由完整下级波段构成，保留子波段关联；确认延迟会逐级传递。

已确认：第一版只使用正式逐级状态，不生成高层临时投影。当前未完成的小级别波段单独展示，不提前作为完整输入提交上一级。

```text
高层正式状态：只根据截至观察日已经完成且可见的下级波段更新；
当前小级别波段：单独展示正在运行的方向、持续时间和幅度；
不将未完成下级波段临时假设为结束来计算高层状态。
```

每个层级须区分 `observation_date`（观察日期）、`last_update_date`（正式状态最近更新日期）和 `data_through_date`（已消费输入覆盖到的日期）。高层时间与幅度只按正式输入计算，不因观察日期推进而伪装成已覆盖当日行情。层级之间更新日期不一致是允许的，界面和预测样本必须保留这种差异。

核心对象包括：

```text
daily_structure_states   每股票/交易日/层级一条的日线结构状态
confirmed_wave_structures 已确认完整走势波段，一条记录代表一个波段
level_relations           相邻层级的父子波段关系
pattern_samples           基于历史重放生成的逐日上下文模式样本
pattern_statistics        模式匹配后的条件统计结果
```

### 3.1 两类结构记录

已确认：第一版同时保留两张结构表，但两者不是同一对象的两套视图，而是不同时间粒度的记录：

#### 日线结构状态表 `daily_structure_states`

一条记录对应一个股票、一个交易日和一个层级，记录该日使用当时已知行情计算出的当前结构状态及表达式。它服务于逐日预测特征、当前状态展示和历史重放结果核验。

```text
主粒度：symbol + trade_date + level_id
内容：当日状态、当前波段起止信息、表达式、数据覆盖日期
规则：只能使用 trade_date 及以前的数据
```

#### 已确认走势结构表 `confirmed_wave_structures`

一条记录对应一个已经确认完成的完整走势波段，记录波段起止日期、最终状态、幅度、持续时间、参考 ATR 和子波段关系。它服务于完整波段展示、人工复盘、向上一级传递已完成输入以及历史周期序列构建。

```text
主粒度：symbol + level_id + start_date + end_date
内容：start_date、end_date、最终 state、幅度、持续时间、子波段日期范围
边界：相邻波段满足前一段 end_date = 后一段 start_date 的前一交易日
规则：只有满足该层正式终止条件的完整波段才能进入；不分配 wave_id 或 segment_id
```

后续行情可能使当前结构重新划分，因此已确认走势结构表允许对尚未稳定的历史结构记录进行更新；但业务上仍只读取当前最新的完整波段结果，不维护多套可选结构视图。第一版不生成、不存储、不传递任何 `wave_id`、`segment_id` 或父子波段 ID；波段通过股票、层级和起止日期识别。历史预测不直接读取今天的已确认结果，而是按历史观察日重放算法。

## 5. 统一轨迹简化与多级波段

### 5.1 目标

将价格轨迹通过 DP 简化为：

```text
UP
DOWN
```

通过轨迹简化保留重要转折点，不把每一个短期波动都保留为独立转折。

L0 波段是最小结构单元，主要用于描述：

```text
当前行情的局部方向
当前中层周期中的短期回调或反弹
走势内部的毛刺与回撤
```

### 5.2 与现有市场结构模块的复用边界

第一版新方案复用项目现有的 `atr_14`，但独立完成多级轨迹简化和波段识别。

```text
复用：现有 atr_14 及其前复权 OHLC 计算口径；
不复用：现有 Swing High / Swing Low 结果；
不复用：现有 BOS / CHoCH 事件；
不复用：现有 cluster_levels 支撑压力结果。
```

`atr_14` 在本方案中只作为各层 DP 偏离归一化的波动尺度。它不用于计算未来收益。

这样可以保持现有市场结构接口与新周期模式实验的职责分离：

```text
现有市场结构：确认 Swing、BOS、CHoCH 和价格参考位；
新周期模式系统：逐级运行 ATR 归一化 DP、生成 UP/DOWN 波段和上下文表达式。
```

### 5.3 价格与波动尺度

第一版 DP 直接处理前复权收盘轨迹，不先把每根日 K 离散成 UP/DOWN/FLAT。这样 L0、L1、L2、L3 完全使用同一个算法。

```text
price_t = 前复权 close_t
log_price_t = log(price_t)
atr_ratio_t = ATR14_t / close_t
```

`atr_14` 只作为 DP 偏离度的归一化尺度，不用于未来收益计算。`high/low` 不参与 DP 的转折点分裂判断。

交易日序号只用于确定点在起止趋势线上的相对位置；价格方向由 DP 保留转折点的端点收盘价决定：

```text
end_close > start_close → UP
end_close < start_close → DOWN
end_close = start_close → 删除零净变化候选
```

### 5.4 第一版核心算法：ATR 归一化 Douglas–Peucker

已确认：第一版不再采用“当前方向 + 阶段极值 + 反向幅度终止”的状态机作为核心波段算法，改用 ATR 归一化的 Douglas–Peucker（DP）轨迹简化算法。

DP 的基本思想是：用一条趋势线连接一段轨迹的起点和终点，寻找中间偏离趋势线最大的点；最大偏离不超过本层容忍阈值时，整段保留为一个波段；超过阈值时，在该点拆分并递归处理左右两段。

第一版统一使用：

```text
输入价格：前复权 close
价格坐标：log(close)
波动尺度：现有 atr_14 / close
偏离度：轨迹点相对起止趋势线的偏离，按 ATR 比例归一化
```

对一段输入轨迹 `[i, j]`：

```text
1. 用 (i, log(close_i)) 和 (j, log(close_j)) 连接趋势线；
2. 计算 i、j 之间每个中间点相对趋势线的 ATR 归一化偏离；
3. 找到最大偏离点 m；
4. max_deviation <= tolerance[level] → 整段保留为一个波段；
5. max_deviation > tolerance[level] → 在 m 处分裂，递归处理 [i, m] 和 [m, j]。
```

这里的“距离”第一版定义为价格方向上的趋势线残差，而不是未经归一化的二维欧氏距离。时间轴只用于计算趋势线位置，不参与距离单位：

```text
u_k = (k - i) / (j - i)
trend_log_close_k = log_close_i
                  + u_k × (log_close_j - log_close_i)
atr_ratio_k = max(ATR14_k / close_k, 1e-8)
deviation_k = abs(log_close_k - trend_log_close_k) / atr_ratio_k
```

对区间 `[i, j]` 取 `deviation_k` 最大的中间点；若最大值严格超过本层 `epsilon` 才分裂，等于阈值不分裂。递归完成后，按日期顺序排列所有保留点，相邻保留点构成波段候选。

第一版不使用垂直距离、欧氏距离、high/low 或累计子段收益作为 DP 分裂依据。这样每个点的偏离都解释为“偏离起止趋势线多少个 ATR”。

### 5.5 多级输入与容忍参数

同一套 ATR 归一化 DP 算法逐级处理，只改变输入单位和固定容忍倍数：

```text
L0：输入日线收盘轨迹；
L1：输入已完成的 L0 波段转折点/端点轨迹；
L2：输入已完成的 L1 波段转折点/端点轨迹；
L3：输入已完成的 L2 波段转折点/端点轨迹。
```

第一版固定参数：

```text
epsilon[L0] = 0.20
epsilon[L1] = 0.80
epsilon[L2] = 2.00
epsilon[L3] = 3.00
```

其中 `L0/L1/L2/L3` 都使用同一 DP 公式；差异只在固定 `epsilon`。`epsilon[L0]=0.20` 沿用现有日线 ATR 比例尺度，不再另建一套 L0 的方向状态机，也不再额外使用 `max(0.3%, ...)` 作为 DP 分裂条件。所有参数都是固定实验超参，不得根据回测结果调整。

高层不能直接扫描原始日线，未完成的下一级波段不能提前提交为高层输入。新行情到来后，当前结构结果允许重新运行 DP 并修正历史转折点和波段边界；历史回测必须按观察日截断数据后重新运行同一算法。

### 5.6 转折点与 UP/DOWN 波段

DP 输出的是按偏离阈值保留下来的转折点序列。对相邻转折点：

```text
end_close > start_close → UP
end_close < start_close → DOWN
end_close = start_close → 删除该零净变化候选；不生成第三种状态
```

第一版不实现 Z 震荡状态，所有层级状态集合固定为：

```text
UP / DOWN
```

如果相邻保留点端点价格不相等，按端点收盘价方向生成 `UP` 或 `DOWN`；如果端点价格相等则删除该零净变化候选，不生成第三种状态。转折点自然成为前后波段的边界；不再额外维护：

```text
反向开始日期；
反向确认日期；
反向持续时长；
阶段极值回溯状态机。
```

DP 只负责抽稀和保留重要转折点；波段总持续时间 `duration` 由相邻转折点的实际交易日区间计算。

第一版实现约束：

```text
输入点少于 2 个 → 不生成波段；
ATR14 缺失或无效 → 该点不能作为 DP 内部偏离点，相关样本区间跳过并记录数据质量问题；
递归区间没有中间点 → 直接保留端点；
递归深度只受输入点数量限制，不设置额外时间或长度终止；
同一最大偏离存在多个点 → 取日期更早的点，保证结果确定；
```

当前最新数据中的最右侧候选波段视为“当前尾段”，进入 `daily_structure_states`；其左侧已经被后续转折点封闭的波段进入 `confirmed_wave_structures`。新数据到来后允许重新运行 DP，表中的当前结果可以被覆盖更新。

### 5.7 第一版明确移除的复杂规则

以下规则不参与第一版波段切割：

```text
极值反向幅度状态机；
反向持续时间超限；
反向连续若干日终止；
从波段起点计算净方向反转；
固定最长周期强制切割；
最短波段长度；
单日波段强制合并；
独立的高低点/BOS/CHoCH 状态机；
Z 震荡状态。
```

反向运行时长不再作为第一版字段；第一版只保留每个完整波段的总持续时间。

### 5.8 波段字段

```json
{
  "level_id": "L2",
  "state": "DOWN",
  "start_date": "2026-02-01",
  "end_date": "2026-03-12",
  "duration": 28,
  "start_close": 30.00,
  "end_close": 24.60,
  "net_return": -0.18,
  "amplitude": 0.23,
  "max_deviation_atr": 2.31,
  "child_segment_ranges": []
}
```

`child_segment_ranges` 只记录下级波段的日期范围和状态，不使用任何波段 ID。已确认走势结构表只收录已经完成的波段；当前未完成波段只出现在日线结构状态表的当前状态中。

### 5.9 结构结果与两张表

第一版同时维护两类不同粒度的当前最新记录：

```text
daily_structure_states    每股票/交易日/层级一条的状态快照
confirmed_wave_structures 已完成波段一条一条记录
```

后续行情可以修正尚未稳定的结构边界和归属，但不保留多套业务版本。第一版不使用任何波段 ID；通过 `symbol + level_id + 日期区间` 识别波段。预测和回测按历史观察日重放同一套 DP 算法，不直接读取后来修正的当前结构。

## 6. 逐级输出与确认边界

### 6.1 层级输入输出

第一版采用：

```text
L0：日线收盘轨迹 → L0 UP/DOWN 波段；
L1：已完成 L0 波段轨迹 → L1 UP/DOWN 波段；
L2：已完成 L1 波段轨迹 → L2 UP/DOWN 波段；
L3：已完成 L2 波段轨迹 → L3 UP/DOWN 波段。
```

上一级只消费已经完成的下一级波段。未完成下级波段可以在自己的日线状态记录中展示，但不能提前作为完整输入提交给上一级。

DP 的递归结果由保留转折点组成；相邻保留转折点之间形成一个完整方向波段。当前结果中最右侧尚未被后续转折点封闭的候选作为当前尾段，只进入 `daily_structure_states`；已经被后续转折点封闭的波段进入 `confirmed_wave_structures`。

### 6.2 当前结果与历史重放

系统只维护当前最新结构结果，但允许后续行情重新运行 DP 并修正尚未稳定的转折点、波段边界和归属。第一版不保存多套结构版本，也不使用波段 ID；波段通过股票、层级和起止日期识别。

预测和回测对每个历史观察日执行：

```text
截断原始数据到观察日；
按相同层级顺序运行 ATR 归一化 DP；
生成当时可见的日线状态和已确认波段；
再连接未来收益标签。
```

### 6.3 延后扩展：Z 震荡状态

Z 不属于第一版。此前确认的 Z 方案保留为后续扩展素材：

```text
非 0 级 Z 状态；
L1/L2/L3 的 Z 最小观察周期 20/40/60；
所有非 0 级统一 15% 的有限价格区间；
Z 的独立波段边界和表达式编码。
```

重新启用 Z 时，需要在 DP 保留转折点的基础上另行定义状态分类和确认边界，不改变第一版 UP/DOWN 核心算法。

## 7. 时间和幅度离散化

### 7.1 时间档位

第一版使用：

```text
[5, 10, 15, 20]
```

第一版固定使用以下区间分箱：

```text
1～7 天       → 5
8～12 天      → 10
13～17 天     → 15
18 天以上     → 20
```

第一版不新增长周期档位；持续时间超过 18 个交易日统一进入 20 档。

### 7.2 幅度档位

第一版使用：

```text
[5%, 10%, 20%, 30%]
```

第一版固定使用以下区间分箱：

```text
0%～5%        → 5
5%～10%       → 10
10%～20%      → 20
20%以上       → 30
```

各层波段：

```text
UP / DOWN → 使用累计涨跌幅绝对值
```

每个层级的当前波段使用同样的分箱口径。

所有档位规则必须纳入 `source_version`，禁止回测过程中按结果调节边界。

## 8. 带历史周期上下文的复合表达式

### 8.1 时间语义与可修正结构结果

本方案不维护两套竞争性的业务视图，而是维护两类不同粒度的当前最新结构记录：日线结构状态和已确认完整波段。系统使用截至最新数据可见的全部行情重新计算或增量修正它们；后续行情可以修正此前尚未稳定的状态、边界和归属，但每类记录都只保留当前最新结果。

```text
current_structure = F(all data available up to now)
new data arrives
→ recompute or revise current_structure
→ replace the previous current_structure
```

第一版日线状态表和已确认走势结构表都只记录 `UP` / `DOWN`。未来启用 Z 后，才可能把窄幅运行与突破整理为“前段 `Z`、后段 `UP`”；该规则属于延期扩展，不进入第一版。

### 8.1.1 历史重放与未来函数隔离

预测样本、历史模式库、条件概率统计和滚动回测不能直接读取今天已经被后续行情修正的当前结构结果。对每个历史观察日 `t`，必须：

```text
截断原始数据到 t；
从历史起点重新运行同一套逐级分段和状态判定算法；
使用重放得到的当时可见表达式生成样本；
再连接 t+5、t+10、t+20 的未来收益标签。
```

历史重放结果是实验过程中的临时快照，不作为第三种长期业务结果保存，也不得覆盖当前最新结构表。这样既允许当前结构随着新数据修正，又保证历史预测不使用未来信息。

#### 已完成的历史周期

只使用已经结束的中层周期：

```text
H[-K], ..., H[-2], H[-1]
```

这些周期可以使用完整的持续时间、最终状态和最终幅度。

#### 当前未完成周期

当前周期还没有结束，因此不能使用其未来最终持续时间和最终涨跌幅。

当前只编码截至当日已经发生的部分：

```text
当前层级状态的实时估计
+
当前层级已持续时间
+
当前层级已实现幅度
```

这条规则是避免未来函数的核心。

### 8.1.1 正式逐级状态与独立层级表达式

已确认：第一版不把 L1、L2、L3 拼成一个复合表达式，而是为每个层级分别生成表达式、分别建立模式库、分别统计未来收益。每条样本通过 `level_id` 标识所属层级。

```text
L0 expression：描述 L0 波段及其历史 L0 波段序列；
L1 expression：描述 L1 波段及其历史 L1 波段序列；
L2 expression：描述 L2 波段及其历史 L2 波段序列；
L3 expression：描述 L3 波段及其历史 L3 波段序列。
```

当前未完成的下一级波段仍不能提前作为完整输入提交上一级。当前结构结果中的正式状态使用当前已知数据计算；历史预测样本则使用对应观察日历史重放得到的状态。当前未完成小级别波段可作为该小级别自己的当前细节，但不拼入高层表达式。

预测样本须保存 `level_id`、`last_update_date`、`data_through_date`；不生成、存储或混入跨层临时投影特征。L1、L2、L3 可以对应同一观察日期，但各层正式状态的更新时间可能不同。

### 8.2 单个已完成波段编码

每个层级的已完成波段统一编码为：

```text
{state}_{time_bin}_{amp_bin}
```

例如：

```text
U_10_10
D_15_20
```

第一版不生成 Z；所有层级表达式的状态字段只允许 U / D。

### 8.3 当前波段编码

每个层级的当前波段使用截至当日已经发生的部分：

```text
{state}_{time_bin}_{amp_bin}
```

当前波段仍未完成时，持续时间和幅度使用当前结构计算截止日的临时值；当前结构后续可以修正。历史预测表达式不读取后续修正结果，而由对应观察日的历史重放重新生成。

### 8.4 K=1 表达式

对每个 `level_id` 独立生成：

```text
[该层上一个已完成波段]#[该层当前波段]
```

示例：

```text
L1: D_10_10#U_5_5
L2: U_15_20#D_10_10
L3: D_20_30#D_15_20
```

### 8.5 K=2 表达式

对每个 `level_id` 独立生成：

```text
[该层倒数第二个波段],[该层上一个波段]#[该层当前波段]
```

示例：

```text
L1: D_10_10,U_10_10#D_15_20
L2: D_15_20,U_10_10#D_20_20
L3: U_20_20,D_20_30#D_20_20
```

这些表达式分别进入 L0、L1、L2、L3 的模式统计，不将多层历史序列拼成一个超长字符串。

已确认：每个层级、每个 `context_k` 独立建样本集。若某层在观察日之前已经完成的历史波段数量少于 `K`，则跳过该层该 `K` 的样本，不自动退化为较短上下文。

```text
L3/K=2 但只有 1 个已完成 L3 波段 → 不生成 L3/K=2 样本；
L3/K=1 且已有 1 个已完成 L3 波段 → 可以生成 L3/K=1 样本。
```

### 8.6 结构化存储

字符串用于索引、展示和人工复盘；结构化字段用于后续近似匹配和统计。

```json
{
  "level_id": "L2",
  "context_k": 2,
  "history": [
    {
      "state": "D",
      "time_bin": 15,
      "amp_bin": 20
    },
    {
      "state": "U",
      "time_bin": 10,
      "amp_bin": 10
    }

  "current": {
    "state": "D",

  },

}
```

## 9. 历史模式库

### 9.1 样本定义

对每只股票的每个交易日生成一条样本：

```json
{
  "symbol": "600489.SH",
  "date": "2026-09-30",
  "level_id": "L2",
  "context_k": 2,
  "expression": "D_15_20,U_10_10#D_20_20",
  "close": 21.90,
  "future_return_5d": 0.032,
  "future_return_10d": -0.018,
  "future_return_20d": 0.061,
  "future_up_5d": true,
  "future_up_10d": false,
  "future_up_20d": true
}
```

### 9.2 未来收益定义

固定定义：

```text
future_return_N = close[t+N] / close[t] - 1
```

其中 `N` 为交易日数量，不是自然日数量。

第一版只使用原始方向标签，不引入交易成本、滑点或固定收益缓冲。

```text
future_return_N > 0  → future_up_N = true
future_return_N <= 0 → future_up_N = false
```

这里的方向标签只用于研究走势模式与未来方向之间是否存在统计关系，不直接代表可交易收益。交易成本相关标签留待后续交易验证阶段。

第一版不使用未来最高价或最低价作为主标签，避免把持有期收益和路径收益混在一起。可以额外记录：

```text
未来 N 日最大有利波动
未来 N 日最大不利波动
```

用于风险分析，但不参与第一版上涨/下跌标签计算。

### 9.3 预测周期与标签可用日期

不同预测周期分别控制历史标签的可用日期，不采用统一按 20 个交易日滞后的方式。

对于预测日期 `t` 和预测周期 `N`：

```text
历史样本日期 <= t - N 个交易日
```

才允许进入该预测周期的模式统计。

因此：

```text
未来 5 日统计：只使用未来 5 日收益标签已经完整实现的历史样本；
未来 10 日统计：只使用未来 10 日收益标签已经完整实现的历史样本；
未来 20 日统计：只使用未来 20 日收益标签已经完整实现的历史样本。
```

这里的 `N` 指交易日数量，不是自然日数量。对于同一个预测日期，5/10/20 日统计可以使用不同的历史样本集合，但它们都必须满足各自标签已经在当时可见的条件。

### 9.4 样本边界

以下样本不进入未来收益统计：

- 未来不足 N 个交易日；
- 未来期间数据缺失；
- 股票长期停牌；
- 数据异常或价格小于等于 0。

### 9.5 版本隔离

每条样本必须记录：

```text
source_version
```

只要以下任一内容发生变化，就必须升级版本：

- 复权口径；
- 底层切割规则；
- 中层聚合规则；
- 时间档位；
- 幅度档位；
- 当前周期的序列化规则；
- 未来收益定义。

不同版本的样本不得混合统计。

## 10. 第一版实验模型

为了验证历史上下文是否有增量信息，至少实现以下模型。

### 模型 0：无条件基准

不考虑表达式，只统计同一时期股票池的整体未来收益：

```text
全市场未来 5/10/20 日上涨概率
全市场平均收益
```

### 模型 A：当前层级状态

对每个 `level_id` 分别只使用当前状态：

```text
L0：U / D
L1：U / D
L2：U / D
L3：U / D
```

这是各层的单点状态基准。

### 模型 B：当前层级状态与当前波段细节

对每个 `level_id` 分别使用：

```text
当前层级状态
当前波段时间档
当前波段幅度档
```

例如：

```text
L2：D_20_20
```

### 模型 C：该层历史周期上下文

对每个 `level_id` 分别使用：

```text
K=1 或 K=2 的该层历史波段序列
+
该层当前波段
```

例如：

```text
L2：D_15_20,U_10_10#D_20_20
```

模型 C 的主比较不是把多层拼接，而是分别回答：

```text
L0 历史波段上下文是否有增量信息？
L1 历史波段上下文是否有增量信息？
L2 历史波段上下文是否有增量信息？
L3 历史波段上下文是否有增量信息？
```

不同层级的覆盖率、样本量和预测效果必须分开报告。

## 11. 匹配与条件统计

### 11.1 第一版只做精确匹配

如果当前表达式为：

```text
D_15_20,U_10_10#D_20_20
```

历史库只匹配完全相同的表达式。

第一阶段不做近似匹配，原因是：

```text
先验证表达式本身是否有统计价值；
如果同时引入模糊匹配，无法判断效果来自表达式还是匹配规则。
```

### 11.2 最小样本数

建议：

```text
有效样本数 < 50：不输出概率；
50～100：输出但标记 low_confidence；
>= 100：正常输出。
```

第一版固定：

```text
MIN_SAMPLE_COUNT = 50
```

### 11.3 输出指标

每个表达式、每个预测周期输出：

```text
match_count
up_count
down_count
up_probability
down_probability
average_return
median_return
p25
p75
positive_mean
negative_mean
profit_loss_ratio
max_loss
```

其中：

```text
profit_loss_ratio = 平均正收益 / 平均负收益绝对值
```

如果没有足够的正收益或负收益样本，应输出空值并附带样本说明，不得伪造盈亏比。

## 12. 滚动实验设计

### 12.1 时间划分

如果数据覆盖范围允许，建议：

```text
训练期：2018-01-01 至 2023-12-31
验证期：2024-01-01 至 2025-12-31
测试期：2026-01-01 至 2026-09-30
```

如果实际数据从更晚年份开始，则保持约 60%/20%/20% 的时间比例，并在实验报告中记录实际区间。

### 12.2 滚动训练方式

不能使用一次性全历史统计。

每个测试日期 `t`：

```text
只使用 t 之前已经发生的历史样本；
匹配当前日期 t 的表达式；
统计未来收益。
```

例如：

```text
截至 2026-03-31 的预测，不能使用 2026-04-01 之后生成的任何历史样本。
```

为降低计算量，可以每月更新一次模式库：

```text
月内使用上个月末以前的样本；
月末统一扩展历史样本边界。
```

### 12.3 标签区间隔离（Purged / Embargo）

滚动验证必须考虑未来收益标签区间与验证区间重叠的问题。

由于第一版最大预测周期为 20 个交易日，训练样本的未来标签区间必须在验证样本开始前结束：

```text
训练样本标签结束日 < 验证样本最早日期
```

训练集与验证集之间至少保留：

```text
20 个交易日 embargo
```

例如，若验证样本从某个交易日开始，则训练集中最后一个可用样本的 20 日未来收益标签必须已经在验证区间开始前完整结束。边界附近不满足条件的训练样本必须剔除，不得为了增加样本量而保留。

该规则适用于：

```text
训练集 → 验证集；
训练集 + 验证集 → 测试集；
每个滚动窗口的历史样本 → 当前评估窗口。
```

这样可以避免训练统计使用的未来收益区间与验证行情区间重叠，降低评估结果偏乐观的风险。

### 12.4 跨股票匹配

第一版正式采用跨股票合并模式库作为主实验口径：

```text
同一个走势表达式可以匹配不同股票的历史样本；
股票代码不是第一版的主匹配键。
```

这样可以提高样本量，优先验证走势表达式是否存在横截面上的普遍统计信息。单股历史匹配不作为第一版主实验口径，留待后续作为对照实验。

以下字段必须保留，但第一版只用于分层分析、样本构成检查和结果解释，不参与主匹配：

```text
symbol
industry
market_cap_bucket
liquidity_bucket
```

后续再增加单股历史匹配作为对照。

## 13. 实验评价指标

### 13.1 样本覆盖率

```text
有足够历史匹配样本的测试样本数
/
全部测试样本数
```

至少比较：

```text
K=1 覆盖率
K=2 覆盖率
```

### 13.2 方向指标

对未来上涨/下跌标签计算：

```text
准确率
Precision
Recall
AUC
Brier Score
Log Loss
```

方向准确率不是唯一目标，必须结合收益分布判断。

### 13.3 收益指标

比较各模型的：

```text
平均未来收益
中位数收益
收益标准差
P25 / P50 / P75
正收益比例
平均正收益
平均负收益
盈亏比
```

### 13.4 增量信息

重点比较：

```text
模型 A - 模型 0
模型 B - 模型 A
模型 C - 模型 B
```

重点回答：

```text
各层当前波段细节是否有增益？
历史周期序列是否还有额外增益？
```

### 13.5 稳定性

分别按以下维度统计：

```text
年份
牛市/熊市/震荡市
股票行业
股票市值区间
样本数量区间
```

一个模式不能只在单一年份或单一市场环境中有效。

## 14. 第一版实验成功标准

### 14.1 必须通过

```text
1. 历史表达式逐日生成，不存在未来函数；
2. 实时表达式与历史回放表达式能够完全一致；
3. K=1、K=2 的样本数量和覆盖率可统计；
4. 同一表达式在不同时间窗口中可以重复检索；
5. 能输出完整收益分布，而不只是上涨概率。
```

### 14.2 值得继续

模型 C 相比模型 B 至少满足部分条件：

```text
未来收益的平均值或中位数有稳定改善；
Brier Score 或 Log Loss 改善；
多个时间区间方向一致；
增益不是由极少数样本贡献；
交易成本前后结论方向没有完全反转。
```

### 14.3 不建议继续的情况

如果出现以下情况，应重新设计分段规则：

```text
K=2 后 90% 以上样本没有足够匹配对象；
同一行情轻微参数变化就产生完全不同表达式；
模型 C 只在一个年份有效；
高概率模式的实际收益分布极不稳定；
所有增益都来自少数表达式；
加入历史上下文后只增加稀疏性，没有增加预测能力。
```

## 18. 风险与限制

### 18.1 分段规则风险

底层切割规则和中层周期结束规则会直接决定表达式。轻微调整阈值可能导致整个模式序列变化，因此必须进行参数敏感性分析，但参数不能根据测试集结果反复调优。

### 18.2 模式稀疏风险

随着 `K` 增大，组合空间快速扩张。建议从 `K=1`、`K=2` 开始，只有在样本覆盖率足够时才考虑更长上下文。

### 18.3 市场非平稳风险

不同年份的市场制度、流动性、行业风格和涨跌结构可能不同。历史模式统计必须按时间区间和市场环境分层检查，不能只看总体平均值。

### 18.4 概率误读风险

上涨概率不等于交易价值。必须同时报告：

```text
样本数量
收益均值与中位数
收益分位数
亏损尾部
盈亏比
交易成本后的结果
```

### 18.5 未来函数风险

当前结构结果允许随着新数据到来而修正，这是产品结构展示和最新分析所需的行为；但不能把修正后的当前结果直接用于历史预测统计。

预测统计必须对每个历史观察日 `t` 执行历史重放：只将原始行情截断到 `t`，重新运行同一套算法，使用当时可见的结构表达式，再连接未来收益标签。任何直接读取当前最新结构结果来生成历史日期特征的做法，都属于未来函数。

```text
当前结构结果：允许被后续数据修正；
历史预测样本：必须由逐日历史重放生成；
历史重放快照：仅服务实验，不作为第二种业务视图。
```

## 19. 最终实验问题

第一版实验最终要回答：

> 在相同的历史滚动验证条件下，对 L1、L2、L3 分别比较“当前层级状态 + 当前波段细节”和“该层前序波段序列 + 当前波段”，历史上下文是否对未来 5/10/20 日收益产生稳定且可重复的增量解释能力？

如果答案为肯定，系统可以继续发展为：

```text
走势形态检索引擎
条件概率分析模块
选股排序特征
策略过滤器
AI 个股分析的结构化证据来源
```

如果答案是否定，也应通过实验定位问题究竟来自：

```text
分段规则
表达式设计
历史样本稀疏
市场非平稳
还是模式本身没有预测增量
```
