# A 股打板策略深度审计

审计日期：2026-10-21。源码快照仍在 `/home/ashare-limitup-survey`，提交号见 `docs/limit-up-strategy-survey.md`。本次只读代码并写审计，没有接入，也没有运行下单程序或未知二进制。

## 1. 本系统可以承接的三层

后续接入时只允许落到这三层，不新开一套行情库或交易进程。

| 层 | 现有入口 | 打板里能放什么 |
|---|---|---|
| 数据源 | 能力矩阵里的 `daily`、`minute`、`full_minute`、`realtime`、`depth5`、`auction`、`financial` | 只复用已有数据集。东方财富、同花顺、雪球、掘金、QMT、PandaData、AKShare 都不新接成抓取器 |
| 因子 | 日线因子和 enriched 列，已有 `limit_up_count_20d`、`limit_up_count_60d`、`consecutive_limit_ups` | 用日线可复算的股性、连板、炸板代理、次日溢价 |
| 策略 | `data/strategies/custom/` 的日线矩阵策略；监控用的分钟信号 | 日线筛选和持有规则。盘中触发只能做成信号，不能做成券商下单 |

已经存在、不应再平行做的策略：涨停基因活跃股、连板股、连板改进版、2 连板特别版、连板接力、断板反包、逼近涨停。市场层已有情绪分（涨停家数、封板率、最高连板、2 板及以上）和主线涨停统计。选股页能用五档的买一/卖一判断涨停是否封住。竞价服务能落匹配额、未匹配额和竞价涨幅，但当前竞价源不可用时会跳过补跑。

日线矩阵没有：封单金额、排队位置、撤单、炸板次数、回封时刻、板块联动强度。五档只有买一/卖一量，且不是全天逐笔。所以「排板」「扫板」现在只能标成缺口，不能假装已经有策略接口。

## 2. 统一数据词汇

后面每个仓库都按这些词归类。

| 词汇 | 含义 | 本系统现状 |
|---|---|---|
| 日线涨停 | 收盘价达到涨停价 | 已有 `signal_limit_up` / `limit_up_price` |
| 触及涨停 | 最高价到涨停价，收盘可以没封住 | 日线的 high 和涨停价能算，尚未做成因子 |
| 炸板 | 盘中封死后被打开 | 日线只能近似成「摸板但收盘未封」；真实次数要分钟或逐笔 |
| 连板 / 首板 | 连续收盘涨停的天数 | 已有连板列和多个策略 |
| 次日溢价 | 涨停次日开盘或收盘相对涨停价的收益 | 日线可算，尚未做成因子 |
| 封单额 | 涨停价上的买单金额 | 只有五档买一量时可粗算 `买一量 × 涨停价`，没有历史队列 |
| 扫板资金 | 把卖盘吃到涨停价所需金额 | 要卖档价格和数量，现只有卖一 |
| 竞价量比 | 集合竞价成交量相对昨日成交量 | 竞价有匹配量，昨日量在日线里，两边还没接成因子 |
| 板块效应 | 同题材同时涨停的家数 | 主线统计有涨停家数，不是盘中实时板块共振 |
| 发单 | 券商委托、撤单、成交 | 本系统没有此层 |

## 3. 分仓库审计

### 3.1 limit-up-sniper

策略分两段。

盘前用近 250 个交易日的日线计算股性：封板成功率、首板封板率、连板率、涨停次数、次日开盘/收盘溢价、次日红盘率。输入列必须同时有「涨停」和「炸板」。输出是候选股票池，不是直接买入。

盘中对池内股票逐 Tick 决定排板或扫板。14:50 后不买，14:30 后才第一次摸板不买。情绪分低于 2.5 不买，情绪数据超过约定秒数视为过期。换手率低于 3% 跳过，15% 到 25% 减仓观察，不低于 25% 拉黑。排板要求最新价和买一都在涨停价、卖一为空，封单额至少 2000 万，并随情绪升到 1.5 亿；同一概念最多持有 2 只。扫板要求卖一已到涨停价，且吃掉可见卖盘的资金不超过 300 万并较上一笔缩小。

数据源：

- 行情和委托：迅投 QMT / xtdata，Tick、持仓、订单。
- 涨停池、炸板池、跌停池、资金流：东方财富页面和 `push2ex.eastmoney.com`、`push2.eastmoney.com`。
- 板块、市场评分：同花顺 / 问财。部分抓取用 Playwright。
- 情绪和板块优先级里还有可选的大模型结果，它不改变硬过滤。

抽象：

- 因子：封板率、首板封板率、涨停次数、次日溢价、次日红盘率。前两项若只用收盘涨停，会把炸板算丢；准确版依赖「触及但未封」因子。
- 策略：不能把 QMT 交易循环接进来。日线候选池与现有「涨停基因活跃股」重叠，但现有策略没有次日溢价和封板率。
- 数据源：不接东方财富和同花顺爬虫。封单和扫板以后只走已有 `depth5`，并明确它不是完整队列。

### 3.2 QMT-QuantLimit

策略很薄。初始化时用 QMT 本地日线，把昨日收盘价按主板 10%、创业板/科创板 20% 四舍五入得到今日涨停价。交易循环订阅行情，最新价等于该涨停价就按配置金额用最新价买入。已经涨停的股票先剔除。没有封单、换手、板块、炸板和卖出规则。涨停价没有处理 ST 的 5%，也没有用交易所涨停价字段。

数据源只有迅投 `xtdata` 日线和实时行情，以及一个文本股票池。舆情选股是编译后的 `.pyc`，规则不可审计。

抽象：不形成新数据源。涨停价本系统已有，且比「收盘价乘固定比例」准确，不应采用它的算法。买入动作属于发单层，不存在对应策略接口。

### 3.3 daban

能看到的策略只有参数和选股脚本，触发逻辑在各平台二进制里，没有源码，本次未运行。

选股脚本调用 `jvUtil.SQL`，需要 token。它先按行业圈定房地产开发、游戏、化纤、有色、旅游酒店，再查询「主板,非ST,昨日首板」，结果写成订阅股票池。

触发参数表示另一种盘中规则：最多 4 个仓，每仓 1 万元；观察 6 秒；涨幅达到 8% 后，秒均涨幅、秒均换手和秒均成交额同时达标才发单；买单 3600 秒未成交则撤。这是临近涨停的速度单，不是封死之后的排板。

数据源：选股是外部 SQL 服务；行情和发单在二进制内，不能确认接口。

抽象：行业和「昨日首板、非 ST、主板」可以变成日线策略过滤，本系统的首板和 ST 信息足够，不必接这个 SQL。6 秒涨速要实时成交，现有分钟信号太粗。二进制不能接入。

### 3.4 Quantitative-strategy 的打二板

这不是盘中排板。它在 09:28 对「昨日首板、前两日没有涨停」的主板股票发单，用涨停价做保护价，实际按市价在后续 Tick 撮合。集合竞价阶段若竞价量低于昨日成交量的 3% 就取消；实盘还要求开盘涨幅在 0 到 6%。另外过滤市值 70 亿到 520 亿、成交额 7 亿到 19 亿、获利盘比例和左压量。11:28 若未涨停且价格高于持仓均价则卖出，14:50 只要未涨停就卖出。涨停定义是收盘价等于交易所涨停价。

数据源全部是掘金：日线、Tick、证券资料里的涨停价、市值、成交额、停牌和 ST。

抽象：

- 数据源不接掘金。竞价量比和开盘涨幅对应本系统 `auction` 加日线成交量，目前竞价源不稳定，不能当已具备。
- 因子：昨日首板、市值、成交额、开盘涨幅。左压量和获利盘本系统没有现成列。
- 策略：和现有「2 连板特别版」都在做可买入的一进二，但买点不同。现有策略是日线持有评分，这份是竞价成交。接入前应先对照两者的样本，避免再做一个看起来不同、交易结果重叠的策略。卖出时点可以做成日线近似，但不能复刻 11:28 的分时条件。

### 3.5 xunlongjue_doc

仓库没有策略实现，只有说明页。文案称每日 9:25 从首板里做硬过滤和评分，最多推 3 只。没有字段、阈值和数据接口可以核对。不能抽象，也不能按文案重写。

### 3.6 skill-b6-limitup-pool

这是涨停池，不是买入策略。每日记录首板、连板数、炸板次数、首次封板和最后回封时间、题材、特殊形态和晋级率。涨停用最高价相对涨停价的极小容差。有分钟线时炸板次数和回封时间按分钟计算；没有分钟线时炸板改用日线回撤代理，回封时间为空。

数据源是 PandaData，账号来自环境变量。分钟额度不够时自动降级。许可证是 GPL-3.0-only，不能把脚本抄进本仓库。

抽象：涨停池应做成由本系统日线衍生的数据集或复盘视图，不做成新数据源。连板和首板已有。日线版炸板可以新增因子「触及涨停且收盘未涨停」。真实炸板次数和回封时刻依赖 `minute` 或 `full_minute`，目前没有这条派生任务。晋级率和次日溢价也可以用日线算。GPL 只约束代码，不约束这些口径；实现必须自己写。

### 3.7 plank

策略不是打板。它抓日线和龙虎榜，买入龙虎榜净买入额靠前的股票，再用历史连板样本估计晋级率。作者写明机器不能感知盘中情绪。

数据源是雪球，请求带登录 Cookie；龙虎榜是另一路 HTTP。项目停在 2022 年。

抽象：龙虎榜净额本系统没有，也不建议为它接雪球 Cookie。晋级率与涨停池重复，用日线即可，不必迁移 Java 爬虫。

### 3.8 short-term-stock-picker

盘后筛选，不是封板买入。近 20 个交易日至少一次涨停，总市值不超过 150 亿，收盘不低于 MA5/10/20 且短均线在长均线之上，近 3 日平均换手率在 0.5% 到 10%，近 5 日均量大于再前 5 日。评分把涨停次数、均线、量比和换手加总。

数据源是 AKShare：`stock_zt_pool_em` 取东方财富涨停池，`stock_zh_a_daily` 取日线。

抽象：不接 AKShare。涨停次数、市值、均线、换手和量比都能用现有日线和因子表达。它和「涨停基因活跃股」重叠；若要保留 150 亿和均线多头，应写成一个薄的日线策略，而不是引入这个脚本。

## 4. 能不能抽象

| 能力 | 落点 | 现在能否做 | 依据 |
|---|---|---|---|
| 收盘涨停、连板、首板、涨停次数 | 已有因子和策略 | 能 | 七个日线策略和连板列 |
| 触及涨停、日线炸板代理、次日溢价、晋级率 | 新日线因子，必要时加复盘视图 | 能，用现有日线 | 不需要新数据源 |
| 竞价量比、竞价涨幅过滤 | 因子，输入是 `auction` + 日线量 | 接口有，数据现在不稳 | 竞价源不可用时会跳过 |
| 封单额、卖一是否到涨停价 | 盘中信号，输入是 `depth5` | 只有实时快照，没有历史队列 | 不能回测排板成交 |
| 炸板次数、回封时刻 | 由 `minute` 派生 | 数据集有，派生任务没有 | 不能抄 GPL 脚本 |
| 板块共振、龙虎榜、外部涨停池 | 不新接 | 不能按原仓库接入 | 爬虫、Cookie、账号或许可证不合 |
| QMT、掘金、二进制发单 | 不建立此层 | 不能 | 本系统没有券商委托 |

## 5. 已落地的日线准备因子

只新增三个股票虚拟因子，没有改现有七个涨停策略，没有排板或扫板，也没有接入外部仓库。

| 因子 | 口径 |
|---|---|
| `broken_limit_count_20d` | 近 20 个交易日中，最高价触及涨停判定价且收盘未封住的次数。判定与炸板信号相同：`raw_high > 0`、`raw_high >= limit_up_price`、`raw_close < limit_up_price` |
| `limit_next_open_premium` | 前一日 `consecutive_limit_ups > 0` 时，当日开盘 / 前日收盘 − 1；否则为空。记在次日 |
| `limit_next_close_premium` | 同样条件下，当日收盘 / 前日收盘 − 1 |

`limit_up_price` 不在日线文件里。因子检验和挖掘在计算前调用现有的 `compute_limit_signals`，只补这一列。次日溢价直接用已保存的连板数，不重算涨停价。

矩阵回测只有在帧上已经带有 `raw_high`、`raw_close`、`limit_up_price` 时才计算摸板次数；缺列会报错，不会把评分悄悄变成 0。首板次日红盘率还没有单独做，可以由次日收盘溢价是否大于 0 来看。

## 6. 还没做

1. 不改现有七个涨停策略。以后如果要用这些因子做过滤，再单独确认。
2. 竞价源恢复并有稳定历史后，再评估一进二的竞价量比。此前不做。
3. 分钟线派生炸板次数和回封时刻单独做，自己实现，不复制 `skill-b6`。
4. 排板和扫板在没有逐笔或可靠五档历史之前不做策略，也不接任何外部下单程序。
