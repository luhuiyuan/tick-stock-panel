## 2. 目标侧现状

目标仓库已有以下相关能力：

- `backend/app/services/auction_service.py`：集合竞价序列、全市场竞价榜、按日落盘和定时扫描。
- `backend/app/api/auction.py`：个股竞价序列、全市场竞价榜、状态和手动扫描 API。
- `backend/app/data_providers/base.py`：竞价数据契约、`get_auction_batch` 和五档深度契约。
- `tickflow_provider.py`、`free_public_provider.py`、`opentdx_provider.py` 及自定义 Provider 已有深度数据入口。
- `depth_service.py` 已有实时五档/封单旁路。
- `daily_pipeline.py` 已有 09:26/15:01 集合竞价扫描任务。

目标侧目前缺少：

- 竞价涨幅/竞价量能类型字段；
- 竞价量两腿快照和历史比值落盘；
- 开盘 5 分钟量能历史比值；
- 竞价路径 09:16–09:25 逐分钟原始采集；
- F3/F6/F7 正式计算因子和经过验证的策略收益结论。

## 3. 关键兼容风险

1. **现有竞价服务不能直接替换**：目标已有标准化 `auction` 数据集和 Provider 能力矩阵，源实现依赖源仓库的 `get_enriched_latest`、实时行情语义和原始 TickFlow 调用，必须适配目标 Provider/能力路由。
2. **数据时点风险**：09:26 快照、09:32 分钟 K 校正、09:30 竞价 K 的可用性依赖具体数据源；缺能力时必须保留 null/降级，不得伪造竞价量。
3. **历史口径风险**：源实现使用本地 `user_data` Parquet 历史文件，目标应复用现有数据目录、原子写和交易日门控，不能新增平行存储协议。
4. **实时 enriched 风险**：竞价字段进入 enriched/自定义信号后，会影响缓存列、依赖解析、历史回测和前端字段选项，需要明确哪些字段是实时专属、哪些可历史回算。
5. **策略结论风险**：源文档中的阈值来自有限样本标定，且 F3/F6/F7 仍处于前瞻采集阶段；迁移不能宣称收益提升，只能验收字段、数据质量和 fail-closed 行为。
6. **竞价路径语义未实证**：源仓库明确要求首个交易日运行 QA，确认五档字段在竞价时段代表匹配价/未匹配量的实际语义；在 QA 通过前不得把原始列命名为已验证因子。
7. **源提交夹带无关内容**：`/trigger-strategy` 调试接口、监控 SSE 兼容修复、趋势指标消融脚本和其他研究脚本不属于本候选核心范围。
