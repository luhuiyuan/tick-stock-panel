## 2. 基建先行：几何 helper（第 16 册 §9 的欠账）

第 16 册留下一条明确的下一步："07 册 21 条占待实现的 72%，需先在 `build_tags` 内建几何 helper（局部极值、趋势线斜率、箱体上下沿），否则每一条都要重复写窗口切片。"

本批在 `build_tags` 的分块循环内新增两个共用 helper：

```python
def seg_ext(x, edges, mode="max"):
    """按 [a,b) 列分段取极值 -> (m, 段数)。列 k = T-(k+1), 列 0 = T-1。"""
    f = np.max if mode == "max" else np.min
    return np.column_stack([f(x[:, a:b], axis=1) for a, b in edges])

def seg_avg(x, edges):
    """按 [a,b) 列分段求忽略缺失的均值 -> (m, 段数); 全缺段记 NaN。"""
    out = []
    for a, b in edges:
        fin = np.isfinite(x[:, a:b])
        cnt = fin.sum(axis=1)
        out.append(np.where(fin, x[:, a:b], 0).sum(axis=1) / np.maximum(cnt, 1))
    return np.column_stack(out)
```

- `seg_ext` 用于分段最高/最低价：对称三角（bit79）、VCP（bit81）、下降楔形（bit83）。
- `seg_avg` 用于分段均额：VCP（bit81）、更高低点放量（bit84）。
- 两段式/三段式窗口都是 `[a,b)` 列切片，与已用的 `Hf/Lf/A` 同源，不额外取窗口、不重复占内存。

**没做趋势线斜率 helper**：探查阶段试写过最小二乘斜率，但 07 册这批里"收敛/倾斜"用**分段极值的相对高低**已足够判定（比拟合斜率更稳健、对异常 K 线不敏感），故没有引入 `slope()`。若后续要做 07-15 圆弧底这类需要平滑曲线的形态，再补不迟。

## 3. 本批核心工作：收紧过松口径

07 册形态描述来自英文技术文献，原文多为**定性结构**（"紧凑盘整""逐级抬高""窄幅停顿"），没有数字阈值。本地打板样本本身是"涨停/接近涨停的强势股"，这些形态天然高发——首轮按宽松阈值跑，命中率高得离谱：

| 形态 | 首轮口径 | 首轮命中 | 收紧后口径 | 最终命中 |
|---|---|---:|---|---:|
| 回踩续涨 | 回踩 MA20×1.03 | 58,126 (39.8%) | ×1.01 + T-1 放量阳线反包 | 17,624 (12.1%) |
| 双底 | 两底差≤5% + 颈线>1.05 | 29,866 (20.4%) | 差≤3% + 颈线>1.10 + 逼近≥100% | 7,708 (5.3%) |
| 更高低点放量 | 量比>1.2 | 35,417 (24.2%) | 量比>2.0 | 22,527 (15.4%) |
| 杯柄 | 杯深<0.92 + 两沿≤8% | 24,557 (16.8%) | 杯深<0.90 + 两沿≤6% + 逼近≥95% | 11,179 (7.7%) |

**判据**：样本量 ≥300（09 册 §7）+ 年度 CV ≤0.4（稳定）。收紧主要解决"区分度"，CV 是另一回事——收紧双底/更高低点/回踩的 CV 反而略升（0.42），说明这几条的年度漂移是**市场状态驱动**的（07-26 原文结论：形态出现频率随 regime 变化），不是阈值问题，故判 P 并登记"待按年标准化"。

**放弃的 3 条**：

| 编号 | 形态 | 首轮命中/CV | 放弃原因 |
|---|---|---|---|
| 07-13 | 头肩底 | 3,843 / 0.60 | 收紧到 CV 可接受时命中跌到 596 以下、CV 反而升到 0.94；三底结构在打板窗口里样本太不稳 |
| 07-15 | 圆弧底 | 2,176 / 0.63 | 需 60 日长窗口，收紧后命中 158（<300）、CV 0.99；碟形在两三年样本里分布极不均 |
| 07-09 | 高位紧旗 | 740 / 0.49 | 收紧到爆发≥40%/窄幅≤8% 后仅 99 笔（<300）；"爆发式上涨"在 A 股涨停样本里太常见，无法与已有 bit53 主升加速区分 |

这 3 条仍标"待实现"，不进位掩码——硬塞会污染一致性检查（E3 要求全部 ≥300）。

## 5. `pre` 属性的边界

8 条全是 `pre`，但和前几批一样，**"pre 可判定"不等于"能当买入信号"**：

- 对称三角/下降楔形的原文都以"向上突破"收尾——那是 T 日（涨停当天）才发生的事。本批只判到"形态已成形"的 T-1 状态，**突破语义被裁掉**，命名沿用原文但语义收窄。
- VCP 的"从最后收缩处突破"同理，不判。
- 杯柄/双底的"突破柄上沿/颈线"改成"T-1 逼近"（≥95% / ≥100%），逼近是 T-1 收盘就有的信息，不是未来函数。
- 这些标签没过样本外验证，不能进 `csg_` 或策略，只做复盘切片。

## 6. 自查与教训

**探查脚本的 NaN 处理**：分段极值用 `np.max/min` 配合 `Hf/Lf`（缺失填 ±inf），分段均值用 `np.where(finite, x, 0)/cnt`——与生产 helper 完全一致。首轮跑出多条 RuntimeWarning（"Mean of empty slice"、"invalid value in divide"），都是全缺段的正常告警，不影响结果（这些记录会被 `need(cols)` 前置条件判为不命中）。生产代码用 `np.maximum(denominator, 1e-9)` 和 `nanmean` 等价写法规避，命中数逐条复刻一致（差异仅 2 笔，来自两次重算间数据推进）。

**分位切点固定**：波动压缩的 `p20=0.379` 是全样本 `amp5/amp20` 的 20% 分位，固化成模块常量 `COMPRESS_P20`，与 01-19 的 `DD60_P33/P67` 同理——不随重算浮动，否则同一笔记录在不同日期会落入不同档，无法跨期比较。
