## 2. 判等分级标准（沿用第 12 册，三级）

| 级别 | 含义 | 翻表动作 |
|---|---|---|
| **E 严格等价** | 原文定量或建议口径逐条吻合，无自定阈值、无遗漏子条件、无代理字段 | 「待实现」→「**已实现**」 |
| **E\* 等价含落地取舍** | 核心口径吻合，仅把原文的**定性词/建议窗口**具体化为数字或固定窗口，取舍逐条登记且只收紧不放松 | 「待实现」→「**已实现**」 |
| **P 部分** | 命中任一：① 分档维度只落一档；② 用代理字段替代缺失数据；③ 原文纯定性、阈值由本轮自定；④ 漏了原文明确列出的子条件 | 「待实现」→「**部分**」 |

与第 12 册的差别：第 12 册处理的是「把已有『部分』标签补齐 T 日决定性动作」，本册处理的是「从零落地全新编号」，因此不存在「部分→已实现」的升级，全部是「待实现→已实现/部分」。

**「已实现」仍只表示分类维度口径齐备、可在研究台直接筛**，不代表阈值经样本外检验、不代表该维度对收益有区分度、更不等于 L3 盘前信号已实现（README 第 2 节定位不变）。

## 6. 位号容量与多 word 位掩码（v0.7 时占满，v0.7.1 已落地改造）

本批把 `TAG_DEFS` 从 37 条扩到 **53 条**，占满 bit **0–52**：

- 后端仍是每笔一个 `int64` 掩码，前端 `hasTag()` 用 `Math.floor(mask / 2**bit) % 2` 算术判位（不用 `1 << bit`，避免 JS 32 位有符号整数截断）。
- `2**53 - 1 = 9,007,199,254,740,991` 恰是 `Number.MAX_SAFE_INTEGER`；53 个位全置 1 正好触顶。前端 `POW2` 长度 53（下标 0–52），再多加一条就会 `POW2[bit] === undefined`。
- 实测 `mask.max() = 8.20×10¹⁵`，已逼近上限（bit52 被置位的样本占 9.98%）。
- `daban_compute.py` 有三条断言：`len(TAG_DEFS)==53`、`bit` 连续 `0..52`、`max(bit) ≤ 52`。**再加第 54 条会直接断言失败，这是有意的护栏，不是 bug**。

**多 word 位掩码已在 v0.7.1 落地**（2026-11-16，零新标签、纯等价结构重构），实际取法与上面的初步设想有一处关键差别——**每个 word 用满 53 位而不是低 52 位**：

- **为什么是 53 位/word**：`2**53-1` 恰是 JS `Number.MAX_SAFE_INTEGER`，53 个位全置 1 仍然精确可判。53 位/word 让现有 53 条全部落在 word0（`word = floor(bit/53)`，`off = bit % 53`），**word0 的数值与改造前逐位相同**——不需要任何数据迁移或重算映射，旧 `tags.parquet`（单列 `tag`）直接就是 word0，兼容读取。
- **后端**（`daban_compute.py`）：常量 `TAG_BITS_PER_WORD = 53`、`TAG_WORDS = max(1, ceil((max_bit+1)/53))`（当前 53 条 → `TAG_WORDS = 1`，加到 bit53 自动变 2）；`build_tags()` 返回 `(n, TAG_WORDS)` 的 int64 矩阵，逐标签 `masks[:, w] |= 1 << off`；断言改为 `max(bit) ≤ 53*TAG_WORDS-1`。`compute()` 的 payload 里 `tags` 变二维、`meta` 新增 `tag_words` / `tag_bits_per_word`。
- **落盘**（`daban_research.py`）：`tags.parquet` 从单列 `tag` 改为 `tag_0..tag_{W-1}` 多列。**兼容策略**：读不到 `tag_0` 但有旧单列 `tag` 且 `TAG_WORDS == 1` 时直接兼容读作 word0（位域完全等价，不必重算）；当 `TAG_WORDS > 1` 而缓存列数不足时一律判「没有标签」、让页面提示重算——**绝不拿 0 补齐**，否则高位标签会永久静默不命中。
- **前端**（`daban.tsx`）：`DabanData.tags: number[][]`；`hasTag(words, bit)` 取 `words[floor(bit/53)]` 再算术判位，缺失的 word 一律按不命中处理；`passFilter` / `toRecord` / 徽章 / 命中统计全部改传整行 words；`filters.tags` 仍是位号数组，AND 语义不变。
