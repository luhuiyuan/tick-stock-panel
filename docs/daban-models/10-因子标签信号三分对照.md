## 0. 结论先行

**167 条里，没有一条能「原样」成为信号。** 原因不是技术做不到，而是语义与粒度：

- 这 167 条是**给一笔已涨停的记录打标**（事件级、事后、多标签），而系统的信号是**每日每股票一列布尔**（面板级、事前、可触发买入）；
- 绝大多数识别条件里含「T 日涨停 / T 日放量 / 收盘突破 / 封板时间」等 **T 日盘中或收盘才成立**的信息，而打板买入在 T+1 开盘 —— 把它们注册成盘前入场信号就是未来函数（因子 DSL 编译期会直接拒绝负 shift，报 `E005`）；
- 真正能升成信号的，不是这些分类本身，而是从中**抽出来的前置形态条件**（「横盘收敛」「超跌」「缩量窄幅」），且必须重新定义、重新验证。

**按落地形态重新归类（167 条全覆盖）**：

| 标记 | 含义 | 条数 | 占比 |
|---|---|---:|---:|
| **F** | 原子特征 / 因子：连续数值，只用 T 日及以前日线，可写成表达式注册 | 14 | 8.4% |
| **T** | 事件级标签：给涨停记录打标，多标签非互斥，落在研究台观察面板 | 92 | 55.1% |
| **S** | 信号：每日全市场扫描的盘前布尔，**原样 0 条** | 0 | 0% |
| **X** | 受限：需 T 日盘中 / 分钟 / 盘口 / 竞价 / 板块 / 消息 / 资金，本地缺失或覆盖不足 | 49 | 29.3% |
| **M** | 方法论 / 顶层原则 / 打分框架 / 定义，不是分类项 | 12 | 7.2% |
| | **合计** | **167** | **100%** |

> **计数口径提示**：本表按「落地形态」归类，`README.md` 第 2 节按「实现状态」归类（已实现 9 / 部分 11 / 待实现 93 / 受限 48 / 待补全 1 / 方法论 5）。**两套计数维度不同、不冲突**，不要互相对账。本表 X=49 略多于 README 的受限 48，是因为把「待补全」「部分但需缺失数据」也按落地形态归入了 X。

**第二个重要发现**：系统里已经有 **26 条成型的形态信号** `P1`~`P26`（`indicators/vendor/hot_money_radar/radar_core.py`），逐日 PIT 扫描、有 `phase`/`signal` 输出、其中 19 条标了 `PATTERN_EFFECTIVE`。它们**本来就是 L3 的现成实现**，且比本库多数条目更成熟（180 日窗口、筹码分布、OBV）。所以正确顺序是 **先复用 P1~P26，再补不重叠的部分**，而不是把 167 条重写成信号。详见第 4 节。

## 1. 判定口径（无歧义定义）

### 1.1 五个标记

| 标记 | 输出形态 | 系统落点 | 能否被策略消费 |
|---|---|---|---|
| **F** 因子 | 连续数值，逐日每股票一列 | `factors/registry.py` + `dsl.py`，物化成列 | 间接（进 `META.scoring` / IC 回测） |
| **T** 标签 | 布尔 / 枚举，**一笔涨停一行** | `data/daban_research/features.parquet`，行号与 `stats` 同序 | **否**，只作复盘切片 |
| **S** 信号 | 布尔，**每日每股票一列** `csg_` | `data/user_data/custom_signals/*.json` 或 Python 形态规则 | **是**（`ENTRY_SIGNALS`、选股器、监控） |
| **X** 受限 | — | 不落地，保留识别方式 | 否 |
| **M** 方法论 | — | 文档约束 / 策略参数 / 打分框架 | 不适用 |

### 1.2 时点判据（决定「能不能升 S」）

| 判据 | 定义 | 允许的最高形态 |
|---|---|---|
| **P0 事前** | 判定所需全部数据在 **T-1 收盘及以前**已存在（前期 K 线、均线、量能、位置） | F、T、**S 候选** |
| **P1 当日** | 需要 **T 日盘中或收盘**数据（涨停事实本身、T 日成交额 / 换手、封板时间、开板次数、分时路径） | T（**仅事后复盘**），不得升 S |
| **P2 事后** | 依赖 T+1 及以后（`boards`、`days`、7 个 `r_*`） | **禁止**进入任何特征 / 标签 / 信号定义；只能作因变量 |

> **硬约束 1**：`S` 只能是 P0。含 P1 条件的条目，其「前置部分」抽出来后可派生 S 候选，但**原条目仍归 T**，两者必须分开写，不能混称。
> **硬约束 2**：`S` 的定义里**不能出现「今日涨停」**。信号是全市场每日扫描出的候选池，涨停只是事后用来检验信号有没有用的标签。
> **硬约束 3**：`T` 多标签、非互斥，禁止把标签当正交因子叠加解读；升 `S` 前必须过样本外验证、按年 / 板位 / 市场状态一致、样本量 ≥ 300（见 `09` 册第 7 节、`08-05`）。

### 1.3 派生关系的书写约定

一条分类可同时有主归属与派生，本表统一写法：

- 「**归**」列 = 主归属（这条最自然的产出形态）；
- 备注里写「**前置可抽 F/S**」= 把识别条件里 P0 部分抽成独立特征或信号候选，**这是新对象，不是原分类**；
- 备注里写「**含 T 日信息**」= 解释为何不能升 S。

## 2. 系统现成设施对照（只读核查）

| 设施 | 定义形式 | 表达力边界 | 对本表的约束 |
|---|---|---|---|
| 因子 `factors/dsl.py` | 受限 DSL，`ts_mean/max/min/delay/zscore/rank` 等 40+ 算子 | `BASE_COLUMNS` **仅 9 列**：`open high low close volume amount turnover_rate prev_close raw_close` | `clu` / `bp` / 涨停价 / 板块**不在基础列**，相关特征须先物化或走虚拟因子 |
| 自定义信号 `strategy/custom_signals.py` | `{left, op, right, leftDays, rightDays}` 多行 AND，列 `csg_` | 约 50 个白名单数值列 + 6 个比较符（`> >= < <= == !=`）+ `contains`；**无窗口聚合** | `range5` / `vol_compress` / `amt_ratio` / `upper_sh` 等派生字段**不在白名单**，复杂形态无法直接表达 |
| 已有形态规则 `hot_money_radar/radar_core.py` | 26 条 Python 规则 `P1`~`P26`，`match_patterns()` 返回 `[{code,name,phase,signal}]` | 180 日窗口、筹码分布、OBV，逐日 PIT | **L3 的现成范式**，优先复用（第 4 节） |
| 策略 `strategy/seeds/*.py` | `META` + `filter()` / `compute_signals()`，`ENTRY_SIGNALS` / `EXIT_SIGNALS` | 5 种 backend | 只有 `S` 能被引用 |
| 打板研究台 `daban_compute.py` | 事件表 `stats`（23 列，146,136 行）+ 前端 `passFilter` | 现成阈值筛选器 `LIMITS`、`cond_masks` | `T` 的落点；`F`/`T` 调阈值纯前端切分，不触发重算 |

> **关键结论**：`S` 若走自定义信号，只能表达「近似版」（`amplitude`≈横盘、`momentum_20d`≈大跌、`vol_ratio_5d`≈放量、`high_60d/low_60d`≈位置）；长上影 / 实体比例 / N 字结构这类必须走 **Python 形态规则**（即 `hot_money_radar` 路线）或先注册成因子并物化。
