> **事件与收益口径（v0.14）**：研究台涨停事件从「收盘封板」改为「**盘中最高价触及涨停价（含炸板未封）**」，买价 = T 日涨停触板价（当日最高价，封板股=收盘价、炸板股>收盘价），T+1 收盘卖；事件池由 146,618 笔增至约 23 万笔。`limit_basis`（CONFIG，默认 `touch`）可切回 `close` 复现旧口径。收益随口径重算（触板 r_t1 胜率约 43.9%，低于封板 59.7%，炸板追高拉低）。标签仍按封板连板数 CLU 计算，事件池混入炸板后各标签命中数/年度 CV 需重新校准（尚未逐条回溯）。改动只作用于打板研究台内部（`daban_lab.py` 自建触板池），不动上游 enriched / streaks，不影响全系统其它模块的涨停口径。

## 2. 状态定义（图例）

| 状态 | 含义 | 能否直接落地 |
|---|---|---|
| **已实现** | 现有代码/`stats` 字段已落地，可直接筛 | 是 |
| **部分** | 有近似字段但不完全等价，或只有部分子条件落地 | 补一点即可 |
| **待实现** | 只用现有日线即可算出，代码还没做 | 是（优先） |
| **受限** | 需本地缺失/覆盖不足的数据源；**仍完整收录识别方式** | 需先补数据 |
| **待补全** | 来源信息不完整，无法给出无歧义识别方式 | 需补资料 |
| **方法论 / 仅参考** | 约束、流程或参考模型，不是分类项 | 不适用 |

**数据门槛缩写**：`日线` = OHLC+成交额（`amount`/`clu` 全历史齐备；本地全历史 **2432** 交易日，见 `meta.calendar`）；`换手率` = `turnover_rate`，**列存在但历史覆盖极低（各年抽样仅 0.2%–0.3% 有值，仅最新分区全量），实际不可用于分类**，见第 13 册 §5；`扩窗口` = 需把 `win_before` 从 6 扩到 20/60/100；`分钟` = 分钟线（仅 2026-08-31 起）；`盘口` = 五档委托（约 5 天）；`竞价` = 集合竞价（空）；`板块` = 板块归属与板块内统计（空）；`消息` = 公告/舆情/龙虎榜（无）；`资金` = 资金流/北向/融资（待核）。

**约束与已知现象**：
- **位掩码是「每笔 TAG_WORDS 个 int64 word」的多 word 结构（v0.7.1）**：每 word 53 位（`2**53-1` 恰是 `Number.MAX_SAFE_INTEGER`，53 位全置 1 仍可精确判位），位号 `bit` 落在 `word = floor(bit/53)` 的 `bit%53` 位；`TAG_WORDS` 随标签数动态算：v0.7.1 时 53 条全在 word0（数值与改造前逐位相同），v0.8 起跨 word0/word1，v0.10 起跨 word1，v0.13 共 94 条仍 `TAG_WORDS=2`（`word1` 最高 bit93，远小于 `2**53-1`），**剩余可用位 12**。后端 `build_tags()` 返回 `(n, TAG_WORDS)` int64 矩阵、断言 `max(bit) ≤ 53*TAG_WORDS-1`；`tags.parquet` 存 `tag_0..tag_{W-1}` 多列，旧单列 `tag` 缓存在 `TAG_WORDS==1` 时直接兼容读、列数不足时判「需重算」绝不拿 0 补齐；前端 `hasTag(words, bit)` 取对应 word 算术判位（不用 `1<<bit`，避免 JS 32 位截断）、缺失 word 一律按不命中，`filters.tags` 用位号数组、AND 语义不变。等价性由**双实现对照**保证：把 `build_tags()` 还原成改造前单 int64 版本、在同一份数据上重算，word0 与 53 条命中数逐笔/逐条全等。细节与验证记录见第 13 册 §6。
- **历史窗口 v0.9 起为 100 根**（`HIST = 100`，原 60）：06-02 地量群要「百日」低量。`C[:, k] == C_{T-(k+1)}`，前 60 列位置含义不变，bit0–60 无需改条件；但**凡是「对整行取 max/min」的地方必须显式切 `[:, :60]`**，否则会随窗口悄悄变口径——v0.9 抓到两处（bit1 的 `lo60`、bit16 的 `mx60`），已修并做逐位回归，见第 15 册 §6。**这正是扩窗口时最容易漏的一类改法**：显式切片的地方不受影响，代码里看不出问题的恰恰是裸 `max(axis=1)`。
- 全部 **94** 条命中数均 ≥300 笔（09 章第 7 节样本量门槛）；最稀有的仍是「超跌小阳堆积」361 笔，v0.8 最小是 bit54 吸筹后突破 693 笔，v0.9 最小是 bit70 大阳双休 436 笔，v0.10 最小是 bit75 反包·炸板型 **379** 笔，v0.12 最小是 bit87 上升三角 **5,047** 笔，v0.13 最小是 bit91 突破缺口 **4,231** 笔。偏宽的切片标签有两类：第四批的实体换手板 30.7%、箱体突破板 27.5%、W底突破板 23.7%，以及第五批的 01-19 三档（各占约 33%，是**分区**不是稀有信号）；v0.9 的 06-02 地量群 21.8%、06-06 过左峰 12.6% 也属偏宽；v0.10 的 bit72 彩虹桥 0.52%、bit75 炸板反包 0.26%、bit76 断板反包 0.31%、bit78 V反转 0.31% 属**偏差**，是本批刻意收紧阈值以过 300 门槛的结果（放宽到 1,900 笔时 CV 会更低但区分度更差）。
- 多标签**非互斥但可能逻辑互斥**：例如「阳包阴」（T-1 为阳线）与「最后一跌」（T-1 为大阴线）AND 交集恒为 0，勾这两个会筛空，属正常现象，不是 bug。第四批 16 条彼此有 **13 对互斥、0 对完全包含**，与旧标签有 2 对完全包含（`bit42 倒锤头 ⊂ bit6 长上影试盘`、`bit46 高位爆量 ⊂ bit16 接近年内高位`），详见第 13 册 §4；第五批另有 **4 对互斥**（`bit54×bit55`、01-19 三档两两互斥）、**1 对包含**（`bit15 乖离超卖 ⊂ bit58 低位板`，5,217 笔全在低位档内），见第 14 册 §5；第六批另加 **3 对互斥**（`bit63×bit68`、`bit64×bit68`、`bit70×bit68`）、**1 对包含**（`bit62 矮将军 ⊂ bit61 地量群`，3,581 笔全含），见第 15 册 §7；第七批另加 **3 对互斥**（`bit75×bit76`、`bit75×bit77`、`bit76×bit77`，**且是人为优先序造成的，不是自然互斥**——改判定顺序就会失效），见第 16 册 §7。累计 **11 对互斥 / 2 对包含**。**互斥/包含的前端提示仍未做**（体检报告第 1 项，用户 v0.7 明确搁置），新增标签后互斥对只增不减；全 79×79 重叠矩阵尚未系统输出（09 册第 7 节第 2 条）。

## 5. 维护规则

1. **编号稳定**：`册号-序号`，一旦分配不复用、不重排；新增维度追加到对应册末尾。
2. **状态更新**：实现一条 → 改「状态」列并在「落点/备注」写字段名或提交号；同时更新第 2 节的汇总计数。
3. **口径优先**：来源给了数字的写「原文定量」；只给口诀的写「原文定性」+「建议口径」，两者分开，不把建议阈值伪装成来源结论（见 `09-字段符号与识别口径.md` 第 5 节）。
4. **受限不删除**：即使本地没有数据，也保留完整识别方式，只标「受限」，等待数据源补齐。
5. **分类多标签**：同一笔可命中多条；固化结论前必须看重叠矩阵与按年稳定性（见 `09` 第 7 节）。
6. **严格等价**：口径逐条吻合才翻「已实现」；近似/代理只能翻「部分」或保持原状态补备注（见第 11 册）；补齐 T 日决定性动作的复盘标签按第 12 册判 E/E\*，但必须标注「复盘专用，非盘前信号」；分档维度只落一档、用代理字段替代缺失数据、原文纯定性而阈值自定的，按第 13 册判 P 并写明「缺什么」。
7. **阈值先查分布**：新增标签定阈值前先跑只读探查脚本算分位数；原文/建议给了数字的照抄、不覆盖；自定阈值必须在校准册登记为「本轮自定」。生产代码命中数须与探查逐条对齐后才翻表。
8. **判等前先查两件事**：① **原文子条件是否全落**——05/06 册这类「量柱+价+位置」组合条目极易只落其中两三条（v0.8 的 06-04 就漏了「为阳线」，命中数虚高 65%）；② **除法分母是否可能为 0**——影线/实体、振幅/最低价这类比值必须显式 `body > 0` 保护，否则 doji 会被除零成 `inf` 误判命中（v0.8 的 06-10 因此虚高 21%）。两条都过了再谈判等，见第 14 册 §4。
