## 1. 目标与定位

把「主力行为/操盘阶段解释股价」做成系统功能：

- **个股级阶段状态机**：吸筹 → 试盘 → 洗盘 → 拉升 → 出货 五阶段
- **编号规则经验库**：每条规则带触发条件 + 证据字段 + 逐条复测结论（含负向结论的诚实标注）
- **可验证**：PIT 无未来函数 + IS/OOS 跨窗口稳定性验证
- **展示**（后期）：K 线叠加阶段标注 + 经验库页

与「大盘行情分类」（regime/phase 情绪周期）分层：本功能回答**个股**处于哪个操盘阶段，不替代大盘状态识别。

## 2. 总原则（来自调研教训）

1. **可证伪优先，叙事殿后**：先跑通验证台，LLM 归因文本放最后（P4，可砍）。
2. **PIT 无未来函数**：发生日 / 首次可见日 / 确认日三分离；历史重放只使用当时可见数据，禁止回填。
3. **经验 = 规则 + 逐条复测结论**：参照 `stock_hot_money_radar.py` 范本，复测为负向的规则如实标注，不粉饰。
4. **复用现有验证台**：规则封装为策略种子 → `strategy_review` 扫描 → `/strategy-combo` 组合探索，不重复造轮子。
5. **跨窗口不稳定即无效**：沿用缠论中枢实验标准（`docs/chan-center-backtest.md`），不追调参数。

## 4. 目标架构

```
L0 数据层   本地 enriched 日线(OHLCV+turnover_rate) + chip 筹码(移植) + 龙虎榜(仅在线展示)
L1 特征层   筹码指标(获利比例/集中度/成本区/套牢区) + 量价特征(量比/缩量/影线/振幅) + 位置特征(60日分位)
L2 状态机   吸筹→试盘→洗盘→拉升→出货 五阶段 + 编号规则 P1~Pn（as-of 逐日重放）
L3 验证层   规则封装为策略种子 → strategy_review 扫描 → strategy-combo IS/OOS 验证
L4 展示层   个股阶段标注页（K线+阶段色带+规则命中+筹码侧栏） + 经验库页
L5 叙事层   （可选）LLM 归因文本，复用 market_recap 流式协议
```

## 5. 分期计划

### P1 期 · MVP 基础

| 任务 | 内容 |
|---|---|
| 1. chip 移植 | 从 `origin/integration/market-intelligence` 精确移植 10 个文件（`backend/app/chip/*`、`api/chip.py`、`tests/test_chip_*.py` × 3、`frontend/src/components/LastStockChip.tsx`），沿用 price-structure-research 的白名单 `git checkout <分支> -- <文件>` 方式 |
| 2. 特征层 | 新增 `backend/app/phase/features.py`：纯函数计算筹码/量价/位置三类特征（polars） |
| 3. 状态机 v1 | 新增 `backend/app/phase/machine.py` + `rules.py`：五阶段判定 + 首批 6-8 条编号规则（候选：低位缩量企稳、试盘长上影、缩量回踩洗盘、高位放量滞涨、放量突破启动、深破缩量收回），每条带触发条件 + 证据字段 + 首次可见日 |
| 4. 离线验证 | `backend/scripts/phase_scan.py`：对指定股票/区间输出阶段标签时间轴；合成数据 PIT 合规测试 |

**P1 验证标准**：chip 3 个测试通过；特征/状态机单测；PIT 测试（截断历史重放结果不变）；不接入路由、不重启服务。

### P2 期 · 经验库与验证（核心交付）

| 任务 | 内容 |
|---|---|
| 1. 规则信号化 | 每条规则封装为策略种子（`backend/app/strategy/seeds/phase_*.py`），注册进 strategy_review |
| 2. 全市场扫描 | 走现有复盘扫描（每次 ≤3 个策略 + 短区间，沿用已验证的防卡死节奏） |
| 3. 经验库表 | 新增 `backend/app/services/phase_library.py`：每规则样本量/胜率/盈亏比/IS/OOS 分割/四段稳定性，输出 `data/phase_lab/library.parquet` |
| 4. 组合探索验证 | 阶段标签作为信号进 `/strategy-combo`，观察与现有 10 个策略的共振/独立性 |

**P2 验证标准**：产出经验库报告，每条规则含跨窗口复测结论（负向结论如实标注）；沿用 strategy-review 口径（1/3/5 日收盘前向收益、成本 0.15%）。

### P3 期 · 页面

| 任务 | 内容 |
|---|---|
| 1. 个股阶段页 | 新自定义页 `/phase-lab`：K 线 + 阶段背景色带 + 规则命中标记 + 筹码分布侧栏（复用 `LastStockChip`） |
| 2. 经验库页 | 规则表（编号/阶段/触发条件/样本量/胜率/复测结论）+ 下钻到信号明细 |

**配色约束**：阶段色带避开红绿（A 股涨跌语义），使用蓝/紫/橙/灰等中性色系，防止与 K 线涨跌混淆。

### P4 期 · 可选叙事（最后做，可砍）

复用 `market_recap.py` 流式协议：输入阶段标签 + 筹码 + 龙虎榜（在线）→ LLM 生成「该票当前处于 X 阶段，依据是……」解释文本，页面明确标注「叙事仅供研究，不构成操作建议」。

## 6. 影响范围、风险与回滚

- **影响**：除 `main.py` 注册路由、策略注册等最小接入点外，全部为新模块/新文件；不改现有已上线功能（rise-research / strategy-review / strategy-combo）。
- **风险**：
  1. chip 是换手率衰减**估算**，非交易所真实持仓（文档与页面需如实标注）；
  2. 阶段判定有主观性，规则阈值需分位数标定（参照 `market_phase.py` 的全市场 p10/p60/p90 方法）；
  3. 规则过拟合——P2 期验证即为此设的卡口，跨窗口不稳即标注无效。
- **回滚**：新模块可整体删除；每期结束工作区保持可交付状态。
- **边界**：本方案不包含提交现有的 23 个结构核心文件与调研报告；P1 的 chip 移植是独立动作。

## 7. 整体验证标准

每期：单测 + PIT 合规 + `tsc -b` / `vite build`（涉前端时）+ API 冒烟 + 不重启服务直至页面期。
整体：P2 期产出一份跨窗口稳定的经验库报告（含负向结论），视为核心交付完成。
