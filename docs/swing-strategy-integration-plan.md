# 高抛低吸策略吸纳实施方案

> 状态: 已实施。网格与海龟按外部源码做独立分批撮合，没有改写旧策略的两条生产循环。
> 日期: 2026-10-23
> 遵循 [CONTRIBUTING.md](../CONTRIBUTING.md) 的数据口径与测试要求。策略文件规范见 [strategy.md](./strategy.md) 与 `backend/app/strategy/prompts/strategy-guide.md`。

本方案把前面讨论过、并且能落在本系统日线股票上的策略收成可直接扫描和回测的策略。分批网格和海龟加仓依赖回测撮合改造；其余策略沿用现有整仓进出。

## 1. 目标与非目标

**目标**

- 新增 5 个可直接使用的日线策略，并随安装种子发放一次（已有同名文件不覆盖，用户删除后不复活）：
  - 布林 + RSI 均值回归
  - 涨停后缩量 N 字低吸
  - 均线分批网格
  - 海龟通道（含最多 4 手加仓）
  - 首板
- 回测两套撮合支持「一只股票多批持仓」：加仓、减一手、清仓。旧策略仍是整仓买进、整仓卖出，结果不变。
- 模拟盘自动下单按差额手数下单。模拟盘账本本身已经能记多批，不重做账本。

**非目标**

- 不把外部仓库拷进本仓库，不使用其回测数字，不使用其中写死的第三方 token。
- 不做盘中排板、扫板、逐笔封单。日线没有这些数据。
- 不引入 XGBoost 或任何外部模型文件。N 字只保留规则部分。
- 不做可转债双低、期货网格、券商实盘。
- 不把沪深 300 月频多因子做成战法。研究线已有 PB、ROE、5 日动量、120 日动量；本方案不新增 DSL 因子。
- 不重写已经能用的打板策略。

## 2. 现状

### 2.1 已有策略（保持不动）

这些文件已经在 `backend/app/strategy/seeds/`，本环境 `data/strategies/custom/` 里也已有，直接使用，不改规则：

| 策略 id | 名称 | 角色 |
| --- | --- | --- |
| `near_limit_up` | 逼近涨停 | 日线打板近似：涨幅大且接近涨停价 |
| `consecutive_limit_ups` | 连板股 | 连板追涨 |
| `limit_up_momentum` | 连板接力 | 连板且当日仍强 |
| `broken_board_recovery` | 断板反包 | 断板后的反包 |
| `active_limit_gene` | 涨停基因活跃股 | 有涨停史、当日缩量休整 |

用户目录里还有自定义策略（连板改进版、二连板、炸板回封二板等）。它们不属于种子，本方案不修改。

已有超跌、回踩、布林上轨突破、MACD 零下回升等种子也不改。新策略和它们的差别写在第 4 节。

### 2.2 撮合限制

`backend/app/backtest/engine.py` 有两套撮合（矩阵版与面板版），都必须改，而且规则保持一致：

- 已持有该标的时，新的买入信号被丢掉（`if asset in positions: continue`，面板版是 `if sym in positions`）。
- 卖出是整笔 `pop`，一个 `entry_price`、一个 `shares`。
- 因此网格不能「跌一格加一手、涨一格卖一手」，海龟不能在持仓上再加单位。卖光之后可以再开下一轮；限制的是持仓期间不能分批。

### 2.3 模拟盘

`backend/app/strategy/paper.py` 已按批次记账：`qty`、`avg_cost`、`lots[{date, qty}]`，卖出 FIFO，T+1 只卖买入日期早于今天的数量。

`backend/app/strategy/paper_auto.py` 仍是整笔：买入按金额算一次数量；卖出信号卖掉可卖数量。分批策略的自动下单要改这里，账本不用改。

## 3. 撮合改造

### 3.1 旧策略行为不变

不要求现有策略改信号。适配规则：

- 未持仓且当日 `entry` 为真、`exit` 为假：目标手数 = 1，按现在的资金槽位一次买完。
- 持仓中且 `exit`、止损、移动止盈或最长持有触发：目标手数 = 0，卖掉全部可卖股数。
- 持仓中再次出现 `entry`：忽略，不加仓。
- 同一天先卖后买：仍拒绝（现有 `sold_today` / `buy_same_day_reentry`）。

这是回归基线。改造前后，现有种子策略在固定小样本上的成交列表必须一致。

### 3.2 新信号：目标手数

`SignalMatrix` 增加可选字段 `target_units: ndarray[int] | None`。`None` 表示走 3.1 的旧语义。

新策略每天对每只股票给出目标手数 `0 .. max_units`。撮合只交易差额，且每天先轧差，不在同一天又买又卖：

- 实际手数 < 目标：买入差额（100 股取整，受现金、总仓位上限、最大持仓只数约束）。
- 实际手数 > 目标：卖出差额，但不超过 T+1 可卖数量。当天新买的批次当天不卖。
- 相等：不动。

买不进（现金不足、涨停封死、停牌）时，实际手数保持不变，下一交易日按新的目标再试。策略不要自己记「我已经买到了」，否则和真实成交分叉。

网格的目标手数必须是价格的函数，不依赖上一笔是否成交。海龟的加仓和止损依赖真实批次，放到撮合里算，不放进策略的假账本。见 3.4。

### 3.3 持仓与成交记录

两套撮合的持仓改为与模拟盘同构：

```text
positions[symbol] = {
  qty, avg_cost,
  lots: [{date, qty, price, unit_shares}],
  unit_shares,          # 本轮第一笔定死，后续加仓不重算
  campaign_start,
  ...原有信号日、评分、最高价等
}
```

- 加仓追加 lot，刷新加权成本。一只股票只要 `qty > 0` 就占一个持仓名额。
- 减仓按 FIFO 扣 lot。被减掉的每一批生成一条 `TradeRecord`（该批的买入价、卖出价、股数、持有天数）。
- 清仓是目标手数 0，卖掉当时可卖的全部；若当天仍有不可卖的新批次，剩余留到下一交易日再卖。
- 期末仍有持仓时，沿用现在的 `end` 平仓，按剩余批次逐批记录。
- 仓位市值用全部批次的市值，不再只用第一笔 `entry_value`。

`unit_shares` 在该标的从 0 变成正的那一笔确定：

- 网格：用策略参数里的固定股数（默认每格 100 股）或固定金额折成整手，取本轮第一笔的结果，写进持仓。
- 海龟：`floor(当时权益 × risk_fraction / (stop_atr × ATR) / 100) × 100`。ATR 用入场信号日的 `atr_14`（策略参数改周期时，由策略把对应 ATR 序列交给撮合，不在撮合里再写一套指标）。之后 3 次加仓都用这个股数。

### 3.4 海龟由撮合执行加仓

海龟策略只输出两个布尔序列，不输出路径相关的目标手数：

- `entry`：收盘价突破前 N 日最高价（不含当日）。
- `exit`：收盘价跌破前 M 日最低价（不含当日）。

撮合在持仓上额外维护 `last_add_price` 与当时的 ATR。每个交易日：

1. `exit` 为真，或收盘价 ≤ 最近加仓价 − `stop_atr` × 该批 ATR：目标手数 = 0。
2. 否则未持仓且 `entry` 为真：目标手数 = 1，并冻结 `unit_shares`。
3. 否则已持仓、手数 < `max_units`、且收盘价 ≥ 最近加仓价 + `add_atr` × 最近一批 ATR：目标手数 = 当前 + 1。
4. 否则目标手数不变。

默认参数对齐短线海龟：`N=10`、`M=5`、`add_atr=0.5`、`stop_atr=2`、`max_units=4`。可选经典预设 `N=20`、`M=10`。可选要求收盘价在 MA20 上方才允许开第一手。加仓不再要求 MA20。

固定百分比 `STOP_LOSS` 与海龟 ATR 止损不要叠两套。海龟策略不设百分比止损，只走上面的 ATR 止损和通道出场。最长持有不设，避免把趋势单提前砍掉。

### 3.5 模拟盘自动下单

`paper_auto.py` 对声明了分批的策略：

- 读持仓 `qty` 和策略当日目标股数（`target_units × unit_shares`，海龟的单位股数存在该持仓上）。
- 差额为正：按差额买入，不按「空仓才买」跳过。
- 差额为负：按差额卖出，且不超过 `sell_capacity` 的可卖数量。
- 未声明分批的策略仍走现在的整笔买卖。

自动下单不在本方案里新做盘中循环。仍由现有信号事件触发。

## 4. 新增策略

种子目录：`backend/app/strategy/seeds/`。发放：`strategy_seeds.py` 增加独立标记（`.seeded_swing_batch`），新装和升级用户都补一次；不覆盖已有文件；写入前走现有安全校验。同步更新 `backend/tests/test_strategy_seeds.py`：新装期望文件集、标记不复活、能被引擎加载。

全部 `asset_types = ["stock"]`，`timeframes = ["1d"]`。网格和海龟用 `matrix_native`。布林 RSI、N 字、首板用现有矩阵或 `filter_history`，信号仍是整仓进出（目标手数只有 0 和 1）。

实施时没有采用本节原稿里的均线目标手数，也没有把海龟收成「每格固定 0.5 ATR、每次相同股数」。规则直接来自已克隆仓库，撮合只在成交成功后改账户。

### 4.1 布林 + RSI 均值回归（`boll_rsi_revert`）

来源：`china-astock-quant/strategies/mean_reversion.py`。RSI 用 Wilder 平滑，布林用总体标准差（ddof=0），不用本仓库现成的样本标准差布林。

- 买：RSI(14) < 30 且收盘 < 布林下轨。
- 卖：收盘回到中轨，或 RSI > 70。`MAX_HOLD_DAYS = 10`。不另加百分比止损。

### 4.2 涨停后缩量 N 字低吸（`n_limit_pullback`）

来源：`N-Rebound/night_screener.py` 顶部常量和 `check_stock_sina`。不拷贝模型文件。

- 上市至少 60 根 K 线。近 7 日涨幅 > 9.5%（源码阈值，不是板块涨停价）。
- 其后收盘都不低于该根 K 线的开盘价。上影线 `(high-close)/close` ≤ 6%。成交量 ≤ 涨停日成交量 × 1.2。60 日高低点位置 ≤ 0.6。
- 卖：上述结构不再成立（含收盘跌破那根开盘价）。源码没有持仓天数和止损，这里也不加。

### 4.3 网格（`grid_trading`）

来源：`akquant/examples/strategies/02_stock_grid_trading.py`。`META["scaled_execution"] = "grid"`，走独立分批账本。

- 空仓先买 10 手。之后相对上一笔真实成交价下跌 `grid_pct`（默认 3%）加 1 手，上涨 `grid_pct` 减 1 手。
- 买不进、卖不出、现金不够时不移动锚，下一根 K 线再试。默认回测成交是次日开盘，锚记成交价，不是信号日收盘价。

### 4.4 海龟通道（`turtle_channel`）

来源：`KHunter/trading/turtle_strategy.py` 短线预设。`scaled_execution = "turtle"`。

- 买：最高价突破前 10 日高点（不含当日），阳线、收盘高于昨收、上影线不超过 4%、收盘在 MA20 上。首仓金额默认 2 万元，按成交价取整手。
- 加仓：相对持仓均价盈利至少 2%，且最高价达到上次加仓信号收盘价 + 0.5 ATR。加仓股数 = 当前股数 / (已加次数+2)，向下取整到 100，至少 100。最多 4 次。ATR 是真实波幅的简单平均。
- 卖：最低价跌破前 5 日低点，或最低价触及均价减 2 ATR。卖出当时可卖的全部。未满 T+1 的新仓当天不卖。

### 4.5 首板（`first_limit_up`）

与连板策略区分开：只要第一板。

- 买：当日涨停，且前一交易日 `consecutive_limit_ups == 0`。排除 ST、上市不足 60 日。可选量比下限（默认关闭，避免把封死缩量的一字板全部滤掉；一字板本身会被现有「收盘封板买不进」规则拒绝）。
- 卖：收盘跌破 MA5，或 `MAX_HOLD_DAYS = 3`。`STOP_LOSS = -0.05`。
- 不实现排板和扫板。

## 5. 分期

每期单独可合并。前一期的测试没过，不开始依赖它的下一期。

| 期 | 内容 | 完成标准 |
| --- | --- | --- |
| P1 | 两套撮合改为批次持仓；旧策略走 3.1 适配 | 现有回测测试通过；新增等价测试：同一段行情上，改造前后旧策略成交价、股数、退出原因一致 |
| P2 | `target_units`、网格策略、种子发放 | 构造单票价格：跌过 1 格只加一手，涨回 1 格只卖一手，现金不足时下一根 K 线再补，不重复记假仓 |
| P3 | 海龟撮合规则与策略 | 突破买 1 手；上涨 0.5 ATR 加到最多 4 手且股数相同；通道跌破或 2 ATR 止损时卖光可卖数量；未满 T+1 的新仓次日才卖 |
| P4 | 布林 RSI、N 字、首板 | 引擎能加载；小样本上买入日、卖出日符合第 4 节；不与第 2.1 节已有策略的 id 冲突 |
| P5 | 模拟盘自动下单差额 | 网格/海龟信号产生买入差额和卖出差额；旧策略自动单仍是整笔；可卖数量不超过 `sell_capacity` |

P4 不依赖 P2/P3，可与 P1 之后并行。P5 放在对应策略之后。

- 种子：更新 `test_strategy_seeds.py` 的新装文件集与「删除不复活」。

- 兼容：P1 必须跑现有 `test_engine_portfolio.py` 与策略加载测试。资源按仓库规则单进程。

本方案实施完成后，技术验收是上述测试。不需要为了读方案做手动操作。策略是否值得实盘使用，要等实施后的回测结果，另行确认，不能把本方案当成收益承诺。

## 7. 风险

- 两套撮合容易改漏一套。P1 用同一组行情对两套跑分批用例。
- 成交记录从「一笔持仓一条」变成「一批一条」后，胜率、持有天数的含义变细。只影响新分批策略；旧策略仍是一批，统计口径不变。
- 网格在单边下跌里会加到 `max_units` 后继续亏损。总回撤保护只是减损，不是对冲。
- 海龟按信号日 ATR 和收盘价判断加仓，成交可以在次日开盘。触发价和成交价可以不同，这与现在所有日线策略的 T+1 成交一致，在策略说明里写明。
- 种子发放不会覆盖用户已经改过的同名文件。若用户目录里已经有同名实验文件，新策略不会替换它。
