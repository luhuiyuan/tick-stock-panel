# 统一价格区域算法设计

## 目标

为个股分析页提供一套对称的支撑/压力识别规则：先识别统一的价格区域，再根据当前价格和突破状态判断区域当前是支撑、压力还是中性。单个 Swing 高低点只作为候选位，不直接绘制为正式支撑/压力线。

## 核心原则

1. 支撑和压力使用同一套价格区域、聚类、触碰和评分规则。
2. 市场结构（Swing、BOS、CHoCH）与价格区域是两个独立图层。
3. 只使用已确认的 Swing 点：`confirmed_date <= analysis_end`。
4. 连续贴着区域的多根 K 线只计为一次触碰事件。
5. 单次触碰不能升级为强区域；至少两次触碰才进入正式区域。
6. 区域突破后允许发生支撑/压力角色转换。
7. 当前有效区域的 `end_date` 表示显示终点；`invalidation_date` 才表示失效日期。为兼容现有前端，active 区域的 `end_date` 暂使用分析截止日。
8. 所有规则必须可以使用截至分析截止日的数据重算，不能依赖未来 K 线。

## 处理流程

```text
K线 -> 已确认 Swing -> 统一价格聚类 -> 触碰事件 -> 反应/突破 -> 角色判断 -> 评分/过滤 -> 输出
```

### 1. 候选点

主要使用 SMC 适配层输出的已确认 Swing High/Low。高点和低点先进入同一个候选点集合，不提前固定为压力或支撑。

### 2. 聚类

价格容差（当前快照）：

```python
zone_tolerance = min(
    max(current_price * 0.008, atr * 0.75),
    current_price * 0.02,
)
```

没有 ATR 时使用 `current_price * 0.008`。按价格排序，聚类内最高价与最低价之差不超过容差则归入同一区域，避免相邻点链式合并过宽。区域中心使用价格中位数；区域半宽为：

```python
zone_half_width = max(current_price * 0.004, atr * 0.35)
```

### 3. 触碰事件

K线满足 `high >= lower and low <= upper` 即触碰区域。连续触碰会合并为一个事件；离开区域至少两根 K 线后重新进入，才计为新触碰。

只统计第一个 Swing 起的触碰；历史证据可早于最终区域确认，但图形起点必须是该区域最后一个成员 Swing 的确认日。每个区域记录：

- `touch_count`
- `touch_dates`
- `last_touch_date`
- `reaction_score`
- `volume_score`
- `total_score`

### 4. 反应

触碰后观察未来最多 10 根已存在 K 线：

- 支撑方向：触碰后的最高价减触碰价；
- 压力方向：触碰价减触碰后的最低价；
- 使用 ATR 标准化；小于 0.5 ATR 不计有效反应，达到 1.5 ATR 为强反应。

实现中按区域在当前快照中的角色计算反应分；历史回测应使用滚动快照以避免回看未来。

### 5. 角色

设当前收盘价为 `current_price`：

- `current_price > upper`：`support`
- `current_price < lower`：`resistance`
- 否则：`neutral`

V1 只输出当前角色的快照（根据最后收盘价判断），不把历史穿越误标为当前角色失效。`status=active/neutral`，`invalidation_date=null`；连续两日有效突破、历史角色翻转事件、失效终点留待下一阶段实现。

### 6. 评分

V1 总分 100：

- 触碰次数：40 分
- 反应幅度：30 分
- 最近性：15 分
- 结构关联：15 分

建议等级：

- `strong`：>= 70
- `medium`：40~69
- `weak`：< 40

`touch_count == 1` 时最高只能是 `weak`。

### 7. 正式区域与候选位

- 正式区域：`touch_count >= 2` 且 `total_score >= 40`；
- 候选位：其他区域，包含单次 Swing；
- 正式区域按综合评分和距离当前价格排序，支撑和压力各最多返回 3 个；
- 候选位单独放入 `candidate_zones`，默认不作为正式横线绘制。

## 输出契约

```json
{
  "price_zones": [],
  "support_zones": [],
  "resistance_zones": [],
  "candidate_zones": [
    {
      "lower": 31.42,
      "upper": 32.14,
      "center": 31.78,
      "role": "resistance",
      "side": "resistance",
      "status": "active",
      "start_date": "2026-03-11",
      "last_touch_date": "2026-03-11",
      "end_date": "2026-09-29",
      "invalidation_date": null,
      "touch_count": 1,
      "strength": "weak",
      "total_score": 8
    }
  ]
}
```

`side` 保留用于兼容旧前端，`role` 是统一模型的当前角色。`start_date` 是最后一个成员 Swing 的确认日，保证不提前绘制最终区域；`touch_dates` 可包含形成前的历史证据。后续前端可以只显示正式区域，候选位仅在用户主动开启时显示。

## 验收标准

1. 高点和低点使用同一套聚类规则。
2. `touch_count=1` 不进入正式支撑/压力列表。
3. 两个价格相近且有多次测试的高低点能够合并为同一区域。
4. 区域角色随当前价格相对位置变化。
5. active 区域的显示终点为分析数据最后日期；生成起点不能早于区域所有成员确认日期。
6. 已确认 Swing 历史在追加未来 K 线后保持前缀稳定。
7. 空数据、缺 ATR、无成交量时仍能安全返回。
8. 旧前端仍可读取 `support_zones/resistance_zones`。

## 后续待办：成交量评分（暂不实现）

记录日期：2026-09-29。

成交量评分已在 V1 实现，作为价格区域质量的辅助维度，不作为支撑/压力区域的决定条件。`volume_score` 为 0~1 的归一化辅助分，`volume_ratio` 为触碰成交量相对历史基准的中位数比例。

### 目标作用

1. 区分低参与度的偶然触碰与高参与度的关键价格区域。
2. 辅助判断支撑反应、压力回落和突破是否可信。
3. 在多个价格接近、结构评分相近的区域之间进行排序。
4. 辅助确认支撑/压力互换，但不单独决定角色转换。

### 建议规则

使用每次触碰日成交量与该日前最多 20 根有效 K 线的平均成交量比较，不把触碰日计入基准，也不使用未来数据：

```python
volume_ratio = touch_volume / mean(volume[index - 20:index])
```

多个触碰事件使用 `volume_ratio` 的中位数，单次异常放量不会独占区域评分。最终成交量最多贡献 15 分，并在总分中占 15%。

建议参考区间：

- `< 0.8`：缩量，参与度较弱；
- `0.8 ~ 1.2`：正常；
- `1.2 ~ 1.8`：明显放量；
- `> 1.8`：强放量。

评分映射为：0.5 倍基准成交量为 0 分，2 倍及以上封顶 15 分；缺少成交量、成交量为零或没有历史基准时贡献 0 分。价格结构、触碰次数和反应幅度仍然是主要依据，避免一次异常放量把孤立 Swing 误判为强支撑或强压力。

### 实现前需要验证

- 不同股票成交量基准是否稳定；
- 除权、停牌、上市初期和异常成交量如何处理；
- 放量突破与放量反转是否需要不同权重；
- 需要离线对比加入成交量前后的区域排序变化；
- 已补充不含 volume 或 volume 为 0 时的降级测试；后续仍需用真实股票样本验证不同成交量分布。
