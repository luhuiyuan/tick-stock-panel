# 主力行为与操盘阶段识别——调研报告

- **调研日期**：2026-11-09
- **调研性质**：只读调研（GitHub/公开资料检索 + 本系统源码核对），未实施任何代码改动
- **研究背景**：在「尽快确认市场处于哪种行情」这一主线下，评估是否存在这样一种实现——用「主力入场 / 吸筹 / 试探 / 拉升 / 出货」等操盘手法解释股价波动，并沉淀为一套可复用的经验体系。

---

## 0. 结论摘要

1. **这类实现存在且是一整类**，业内统称「主力行为 / 操盘阶段识别」，学理源头是威科夫方法（Wyckoff）的"综合人"（Composite Man）假设，A 股本土叫「跟庄 / 坐庄五步曲」。
2. **"形成一套经验"的最佳范本是编号规则表 + 逐条复测结论**（B 类路线），不是单纯的阶段标签，也不是 LLM 复盘文本。
3. 本系统**有零件、无体系**：已有情绪周期 6 阶段状态机、筹码分布算法（仅在远端分支）、缠论中枢结构、AI 复盘叙事、若干带"洗盘/拉升"措辞的策略种子，但没有把主力行为做成带编号、带验证结论、可回测的经验库。
4. **方法论风险突出**：「主力在吸筹/试盘」是对不可观测主体的意图归因，天然不可证伪，必须靠 PIT 无未来函数标签、编号规则表带复测结论、跨窗口样本外验证三件事约束，否则只是叙事。
5. 它与你前几轮要的「尽快确认市场处于哪种行情」是**两个不同目标**：状态识别可证伪，归因解释不可证伪；两者应分层实现，不应混为一谈。

---

## 1. 研究问题定义

用户诉求可以拆成三层：

| 层 | 问题 | 性质 |
|---|---|---|
| 解释层 | 股价为什么波动？是主力在吸筹/试探/拉升/出货吗？ | **归因叙事**，对不可观测主体的意图推断 |
| 阶段层 | 能否把走势切成吸筹→试盘→洗盘→拉升→出货等阶段？ | **状态识别 / 阶段状态机**，可做成规则标签 |
| 经验层 | 能否沉淀成一套经验（规则 + 验证结论）供复用？ | **知识工程**，需要每条规则带证据与复测结果 |

三层难度递增：阶段层可工程化，解释层天然模糊，经验层要求可证伪 + 可复现。

## 2. 学理来源与术语体系

### 2.1 威科夫方法（Wyckoff Method）

百年前的价量分析框架，核心是把市场想象成单一"综合人"（Composite Man）在运作，价格结构分为四阶段：

- **吸筹 Accumulation**：低位横盘、缩量后间歇放量、弹簧效应（Spring）、最后支撑点（LPS）、力量信号（SOS）
- **拉升 Markup**：高点低点同步抬升（HH/HL）、上涨放量
- **派发 Distribution**：高位滞涨、放量不涨、上冲回落（UT/UTAD）、弱势信号（SOW）
- **回落 Markdown**：低点高点同步下移（LH/LL）、下跌放量

吸筹/派发区内部有标准事件序列：
`PS → SC → AR → ST → Spring → SOS → LPS`（吸筹）
`PSY → BC → AR → ST → UTAD → SOW → LPSY`（派发）

**判据核心是 Effort vs Result**：成交量（努力）与价格结果背离时，说明有被动大单在承接或派发——高量窄幅=吸收（absorption），高量宽幅弱收=派发。这是"解释主力意图"的量化抓手。

### 2.2 A 股本土「坐庄五步曲」

国内语境的等价物，阶段划分更细（低吸筹码 → 试盘吸货与震仓打压 → 大幅拉升 → 拉升途中洗盘 → 抛货离场），强调行为心理学叙事：吸筹期放利空、出货期放利好、拉升不给低位追进机会、洗盘逼迫浮筹出局。这类资料广泛流传（如[央视网财经的解析](https://finance.cctv.com/20070226/104365.shtml)、[东方财富博客](https://blog.eastmoney.com/wjl179153672/blog_217411336.html)、[股旁网筹码分布教程](https://www.gupang.com/202008/52668.html)），但多为经验文字，缺乏可验证实现。

### 2.3 可观测量代理学派

不假设"主力"存在，改用可计算的量反推大资金行为：筹码分布迁移（CYQ）、龙虎榜/资金流、大单净流入、订单流（CVD/Delta 背离、Footprint 失衡、冰山单、absorption）。这是三条路线里**最可证伪**的一条。

## 4. "形成一套经验"的两个范本解剖

### 4.1 编号规则表范本：`stock_hot_money_radar.py`

这是最贴近「把操盘手法沉淀成一套经验」的实现。做法：

- 把主力行为切成 5 个阶段（吸筹→试盘/洗盘→突破/拉升→出货），逐条编成 **P1~P26 编号规则**，每条写清价格特征 + 量能特征 + 资金流特征，例如：
  - P1 低位缩量企稳复合确认（吸筹）
  - P6 试盘长上影（近 8 日长上影创 20 日新高后收盘缩回）
  - P8 缩量回踩洗盘（站上 MA20 + 回踩近 10 日高点 -2%~-15% + 跌日缩量）
  - P14 高位放量滞涨（出货预警）
- 阶段优先级：出货预警 > 突破 > 吸筹/洗盘 > 拉升 > 试盘。
- **关键**：每条规则明确标注验证结论——「全历史复测为负向风险」「保留形态观测，不作为有效因子」「复测 2 日动量有效，10~40 日转为反转风险」。

经验不是"写下来"，而是"每条都留了可复现的验证结论"。

### 4.2 闭环架构范本：`YoungCan-Wang/Wyckoff-Analysis`

764 star、面向 A 股的完整产品，把"经验→规则→验证→复盘"做成流水线（详见 [PyPI](https://pypi.org/project/youngcan-wyckoff-analysis/0.1.22/)）：

```
五层漏斗（六通道：主升/点火/潜伏/吸筹/地量/护盘）
  → L4 微观狙击（Spring / LPS / SOS / EVR 四大触发信号）
  → L5 LLM 三阵营研报（逻辑破产 / 储备营地 / 起跳板）
  → 信号确认池（L4 触发信号经 1-3 天价格确认后才可操作）
  → 日线回测（回放漏斗命中后 N 日收益，输出胜率/Sharpe/最大回撤）
```

配套 LLM 对话 Agent、持仓诊断、盘前风控、推荐跟踪重定价，且有 GitHub Actions 每日自动化。**这是"经验库"落地为可用系统的参考架构。**

## 6. 方法论风险：归因叙事的可证伪性

这类体系必须与三个内生风险共处：

1. **不可证伪 → 过拟合叙事**：同一个"低位缩量"既可以叫吸筹也可以叫无人问津，事后总能自圆其说。`stock_hot_money_radar.py` 自己就写明多条规则"全历史复测为负向风险""保留形态观测不作为有效因子"——说明经验库里大部分条目经不起全样本检验。
2. **主体假设已弱化**：注册制 + 量化 + 监管环境下，"单一主力按五步坐庄"很多时候是市场合力或算法执行留下的痕迹；拟人化为"主力意图"会引入系统性误判。
3. **确认延迟**：吸筹/派发是区间级概念，往往要几十根 K 线才成立，做不到"尽快确认"——与之前研究主线的目标冲突。

旁证：本会话此前缠论中枢实验（`docs/chan-center-backtest.md`）的结论同样如此——开发窗口的改善未延续到保留窗口，"未找到跨窗口稳定同时改善收益和回撤的方案"。**任何经验规则，跨窗口不成立就不能称经验。**

要把它做成真经验，至少需要三件事：

- 每条规则 **PIT / 无未来函数**：区分发生日 vs 首次可见日 vs 确认日，只用当时可见数据；
- **编号规则表**带触发条件 + 证据 + 复测结论 + 置信度 + 样本外表现；
- **跨窗口样本外验证 + IS/OOS 分割**（本系统 `/strategy-combo` 已有此能力）。

## 7. 与研究主线的关系：状态识别 ≠ 归因解释

| | 状态识别（之前主线） | 归因解释（本次主题） |
|---|---|---|
| 目标 | 尽快确认市场处于哪种行情 | 解释股价波动的原因（主力在做什么） |
| 可证伪性 | 高（标签对错可检验） | 低（意图不可观测） |
| 确认延迟 | 可优化到当日收盘 / 盘中 | 天然滞后（区间级） |
| 工程路径 | 低延迟指标层 / 在线变点（CUSUM/BOCPD） | 阶段状态机 + 编号规则表 + 验证台 |

两者应**分层实现**：先用可证伪的状态识别打底，归因解释作为上层的叙事包装与经验沉淀，不能让叙事替代验证。

## 8. 落地路径建议（未实施，仅建议）

如需在本系统落地，建议步骤：

1. **移植筹码算法**：把远端 `integration/market-intelligence` 分支的 `chip/*`（CYQ 算法 + 测试 + 前端 `LastStockChip.tsx`）移植到当前分支；
2. **定义阶段事件词表与编号规则**：参考 Wyckoff 事件序列 + A 股本土阶段，给出每条规则的价格/量能/资金流触发条件；
3. **无未来函数逐日重放打标签**：区分发生日/首次可见日/确认日，禁止回填；
4. **用 `/strategy-combo` 验证胜率增量**：把阶段标签作为信号/特征丢入 11474 条信号池，看 IS/OOS 稳定性；
5. **沉淀经验库**：每条规则带复测结论、置信度、样本外表现，配一个可回测验证页。

**注意**：以上为建议，本次仅交付调研文档，未实施任何改动。
